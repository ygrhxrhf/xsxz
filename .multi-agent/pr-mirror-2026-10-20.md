# 整站镜像：分类页 → 批量入书库

> 分支 `master`（11 个提交，`origin/master..HEAD`），16 个文件，+1543 / −12。

## 一句话

在内置浏览里打开分类 / 作者 / 搜索结果页，一次把这个列表（含同源「下一页」）里的书批量下进书库；已经完整入库的书按 `sourceUrl` 跳过，取消或进程崩溃后能接着上次的书目继续。

## 为什么

以前只有「下载本书」：N 本书就是 N 次「打开 → 点下载 → 等」。整站镜像把这件事变成一次操作，并且让「中断」变成可以接着做、而不是从头再来。

## 行为契约（详见 `docs/ipc-contract.md`「整站镜像」）

- `seedUrl` 省略时取当前浏览页；非 http(s) 拒绝。`maxBooks` 缺省 10、夹紧 1–50；`maxPages` 缺省 3、夹紧 1–10。
- 发现：只取同源链接，排除导航 / 登录 / 搜索 / 分页 / 资源后缀与重复地址；按 `/book/`、`/novel/` 等路径特征打分，都没有特征时退回已过滤的同源链接。列表页沿「下一页」链串行扫描，最多 10 页。
- 跳过：每本开始前用书目地址的规范化值与书库对照。已完整 → `skipped`，不加载不下载；只下了一半 → 仍交给下载层补章。书库是唯一真值，镜像日志不保存「已下过」的快照。
- 串行：上一本 `waitForIdle` 结束才开下一本；单本失败（含等待超时）只记 `failed`，不终止整批。`mirror.cancel` 在书目之间生效，正在下的那本走 `download.cancel` 且不写结果。
- 续跑：`resume: true` 只接受相同 `seedUrl` 且仍有待办的任务，从 `plan` 里继续；进程中途退出时启动阶段把遗留 `running` 降级为 `cancelled` + `interrupted`，界面据此给「继续上次」。
- 状态落盘 `userData/mirror-state.json`（只留最近一次，含 `plan`），`mirror.state` 返回 `{ running, last }`。
- 复用既有下载通道（隐藏视图逐章 `loadURL`），不绕登录态、不裸 `fetch`、不并发下载。

## 已知边界

- **撞墙不自动解锁**：章节撞墙（付费墙）时下载层会一直占着单任务锁，镜像这一本最多等 30 分钟才记 `failed`；批量镜像遇到墙建议先手动取消，处理完墙再用「继续上次」。
- 不做跨域、不做站内搜索接口、不做代登录、不做并发下载、不做多列表页并发。
- 发现依赖启发式（同源 + 路径特征）。没有站点规则的新站可能漏书，或把「看起来像书目」的链接当书；这类站点走「站点 CSS 规则」再镜像更稳。
- 只跟同源「下一页」，不解析 `?page=` 之外的分页形式。

## 合并后手动验收

1. 浏览页打开一个分类页 → 点「镜像本页」→ 抽屉里逐本看进度，结束态 `done`。
2. 对同一个列表再点一次 → 每本都应是「已在书库」，不重新下载。
3. 中途点取消 → 关掉抽屉重开 → 出现「继续上次」，点了从剩下的书继续。
4. 手动删掉某本里几章再镜像同一列表 → 应只补缺章，不重下整本。
5. 断网 / 杀进程重开 → 上次的 `running` 显示为被中断，可继续。
