## 5. 结论与依据

**结论 A。**

1. `App.vue` 在本刀范围内零 diff；其 `onMounted` 会对带 `progress` 的书直接 `currentBookId + tab='reader'`，夹具书 `d_reader` 正好带 `progress` → 启动瞬间自动进 reader 并完成唯一一次 `loadBook`，弹提示的机会在那一刻。
2. 原脚本的 Observer 要「进书库 → 找到书卡」之后才 arm；实测 arm 时刻页面已在 reader 内且章节已定位（`chTitle="第二章"`），提示早已弹完并自动消失。`[诊断]` 的 `msgCount=0` 是**已消失**，不是**没弹**。
3. 原时序三次跑出 11/11、10/11、11/11；摆动只由 arm 与章节加载的先后决定。EARLY 模式两次稳定 11/11，`resumeFlag=true` 出现在「点书卡」之前。
4. 观察窗内那次 `loadBook` 确实弹了提示（`resumeFlag=true`、`msgTexts=["已回到上次读到：第 2 章 · 第二章"]`），不存在「观察窗内 loadBook 未弹提示」的产品回归。
5. `msgCount=0` 不是有效反证：`msgContainerNull` 在 toast 消失后实测可为 `true`（Naive UI message 容器按需创建/卸载），拿 `msgCount` 判「没弹」本身判据不可靠。
