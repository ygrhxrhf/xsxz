# 适合本仓库的 Jev 开发流程

> 给小说浏览器（spbf）用。Jev 是 TypeSafe 的 System One：吃状态，吐 Choice / Noul / Score 和概率。它不写代码、不生成正文、不改契约。
>
> 事实来源：<https://docs.typesafe.ai/concepts/how-to-build-with-system-one.md>。问题写法以在线文档为准，不要凭记忆发明字段。

## 一句话

代码握流程。凡是代码算不出的语义，默认由 Jev 拍板并直接执行。拿不准、超时、没 Key，走不损坏数据的自动退路。只有退路本身会毁掉用户数据时，才停下来问人。

## 三条路

按这个顺序，不准跳到问人：

| 路 | 何时 | 做什么 |
|---|---|---|
| Jev 做 | 有答案，且该动作可撤销，或只是挑选、标记、丢弃低质量结果 | 代码立刻执行得分最高的选项 |
| 自动退路 | 概率挤在 0.5 附近、超时、429、没 Key、选项是「都不是」 | 留下原文、留下上次已保存的结果，或维持现有提取。不生成待办，不弹窗 |
| 问人 | 上面两条都会删掉无法恢复的数据 | 用现有确认框。不新做复核队列 |

只选最优时取得分最高的选项，不设一道「请用户确认」的中间阈值。阈值只用于区分「做」和「退路」，写死在 `decide.ts`，不由每次运行时的人来调。

已有的移入回收站、删除站点规则、恢复备份，仍走原来的确认框。那是破坏性操作，不是内容判断，Jev 不能替掉。

## 三层分工

| 层 | 谁 | 做什么 | 不做什么 |
|---|---|---|---|
| 代码 | 主进程 | 规则、磁盘、IPC、进度、取消、执行 Jev 的决定、自动退路 | 不把语义判断硬编码成脆正则，也不把判断抛回界面 |
| Jev | System 1 | 同一段状态上的并行判断 | 不写回复、不解释、不自己决定下一步 |
| 现有 LLM | System 2 | 清正文、摘要、翻译、聊书 | 不拿来做每章一次的是/否门 |

渲染进程不持有 `TYPESAFE_API_KEY`。Key 只在主进程读环境变量，不进仓库、不进设置页的小说 API Key 字段。没 Key 时走自动退路，浏览、下载、阅读照旧。

## 什么时候才加一个判断

两条同时成立才进清单，否则留在代码或留在现有 LLM：

1. 答案是「选一个 / 是或否 / 某个程度上」，不是一段文字。
2. 稳定规则算不出来（章数、路径、是否缺 Key、是否已有这本书，都别问模型）。

每条判断必须写明自动退路。写不出退路、又会毁数据的，不加这条判断。

本仓库按这个顺序加，不要跳：

| 顺序 | 判断 | 类型 | Jev 做 | 自动退路 |
|---|---|---|---|---|
| 1 | 抽出的文本是正文，还是目录/导航/广告残页 | Noul | 像正文就当正文用；不像就标残页并进入失败章清单 | 保存原文，不当作残页丢弃 |
| 2 | 失败原因落在现有文案桶：找不到目录 / 正文为空 / 需要登录 / 被拦截 | Choice，必须有「说不清」 | 显示对应的现有文案 | 显示「说不清」，不发明新文案 |
| 3 | 摘要句子是否被本章正文支持；是否越出本章 | 每句一条 Noul | 删掉撑不住或越界的句子，其余保存 | 整段摘要不更新，留着上一份 |
| 4 | 本站 CSS 抽出来的片段是否像正文 | Noul | 像就采用 | 继续走现有通用提取 |

下载状态机、重复书、单下载锁、皮肤枚举、进度条，继续用代码。

## 下一档（前四条影子日志稳定后再做）

都挂在现有 AI 上，且必须由用户先触发。Jev 不写清正文、摘要、译文、前情、记忆或回答。写完后的取舍由 Jev 做完，不送去预览等待。

| 判断 | 类型 | 挂在哪 | Jev 做 | 自动退路 |
|---|---|---|---|---|
| 清理稿是否删掉了原文里的叙述；是否还留着导航或广告 | 两条 Noul | 清正文 | 两条都过才写入 `body`，`bodyRaw` 留下可撤销 | 任一条不通过就保持原 `body` |
| 模型引用的摘录是否支撑回答里的这一句 | 每句一条 Noul | 证据问答 | 删掉撑不住的句子 | 一句不剩就用现有「证据不足」 |
| 代码检索出的摘录里，哪几条和问题有关 | 每条 Score | 送去写回答之前 | 只把高分摘录送去写 | 一条都不剩就用现有关键词结果 |
| 新出现的人物是否就是记忆里的某一人 | 每个候选人一条 Noul | 小说记忆合并 | 明显高于其他人就合并 | 不确定就保持两人 |
| 摘要或前情是否写出了阅读进度之后的情节 | Noul | 本章摘要、前情提要 | 没有越界就保存并展示 | 不展示这版，保留上一次已保存的 |
| 代码切出的多个文本块里，哪一块是章节正文 | Choice，含「都不是」 | 通用提取或本站规则之后 | 采用被选中的那一块 | 「都不是」就维持现在的提取结果 |

证据问答里「让模型生成检索词」不要改成 Jev。Jev 给不出新字符串。检索词继续由代码从已读正文和记忆里的人名、地名取出，再让 Jev 打分。

导入 txt 的「第x章」切分、书名是否同一本、广告请求过滤，规则已经够用，先别加。翻译是否通顺仍交给现有模型；若要核对，只问「是不是现代汉语」，不像就自动保留原文，不问人。

## 嵌进现有战役

Jev 不单独开一条产品战役，也不为每条判断停下来等人点头。

1. **倒推。** 从完成定义写：要留下什么、要丢掉什么。先列出判断和自动退路，再写问题。
2. **砍到代码。** 能算的留下。剩下的每条写成一个窄问题，不写成「这段好不好」。
3. **问题和退路放在一处。** `src/main/jev/questions.ts` 放问题，`decide.ts` 放「答案 → 动作或退路」。工人可以改措辞，但一个问题只能有一个动作和一个退路，不能加人工分支。
4. **用夹具，不让人打标签。** `fixtures/` 里放脱敏的正文、残页、广告页。活调用只对照夹具，不新开一轮人工标注。
5. **影子只用来对日志。** 主进程先走老路径，旁边记 Jev 的答案和概率。和夹具不一致就改问题，不要把样本送给人看。一致后直接接线。
6. **接线。** 新 IPC 名仍走协调者补丁。接线后的默认行为就是 Jev 做或自动退路。

代表行为是一条不用人介入的结果。例如残页章自己进入失败章清单，正常章不进。日志要带 commit 和模型版本。

## 问题写法

- 一个问题只判断一件事。垃圾页拆成：像导航、几乎没有叙述、重复站点套话。是否留下由代码加权，权重写死。
- 同一段状态上彼此独立的问题一次问完。后一个问题要依赖前一个答案、或要先再取正文时，才发第二次。
- 状态用有名字的 JSON，只放这段判断要用的字段。问题里用反引号路径，例如 `` `chapter.text` ``。
- Noul 接近 0.5 是「是和否都像」，不是「程度中等」。这时走退路，不要解释成中等质量。程度用 Score，等级写成具体情形，不写「中等」。
- Choice / Score 的 confidence 只表示概率挤在一个选项上，不表示整条下载是对的。分散时走退路。
- 选项必须有「都不是」。「都不是」就是退路，不是待复核。
- 问法让高概率表示「是」。不要写一个高概率反而表示「否」的问题。

## 文件与所有权

```
src/main/jev/questions.ts   问题与选项。退路不能写成「问用户」
src/main/jev/decide.ts      AI 工。纯函数：答案 → 动作或退路。单测不打网
src/main/jev/client.ts      AI 工。唯一网络出口，读 TYPESAFE_API_KEY
```

- `decide.ts` 不知道网络。测试喂假答案，覆盖「做」和「退路」，不覆盖「等人」。
- 活调用另开脚本，沿用 `npm run test:live-ai` 的规矩：Key 只来自环境变量，样本用夹具，输出脱敏。
- 下载工、阅读工只消费动作，不写问题，不直接调 API。
- 不改 `src/preload/index.ts`，除非协调者把某个只读结果列入白名单。
- 类型字段要新增时走契约补丁，不在问题文件里夹带。

## 放行标准

| 阶段 | 用户看见的 | 过关线 |
|---|---|---|
| 影子 | 与现在完全一样 | 日志里有问题 id、模型版本、概率；失败不影响下载 |
| 对照夹具 | 仍以老路径为准 | 夹具里的残页/正文方向一致；「都不是」走退路 |
| 放行 | Jev 直接执行，或静默退路 | 没 Key、超时、429 都退回老行为；界面不出现复核入口；`npm test` 与 `npm run typecheck` 通过 |

模型版本写进日志。问题改了就用同一批夹具再跑，不沿用旧日志，也不换人重标。

## 不要做

- 为内容判断做复核队列、预览确认或「请用户看看」。
- 用 Jev 生成清正文、摘要、译文、前情、人物卡或问答正文。
- 让 Jev 或编程代理决定产品范围、文案表、禁令。
- 在渲染进程调 Jev。
- 用 Jev 选择下载策略、改 `loadURL` 主路径、或判断如何通过登录墙。
- 用 Jev 取消回收站、删规则、恢复备份的现有确认框。
- 串行一问一答，或把整站 HTML 塞进状态。
- 把 Key 写进设置同步、书库或 git。
