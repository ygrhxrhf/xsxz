# 经验库

> 原则性 > 数值性；模式级 > 页面级；可迁移 > 可复制。不要提交进 Git。

## 历史调研（DeepSeek 可信小说助手）

- 单机 BYOK 产品的成熟度依赖防剧透边界、来源可核验、持续记忆和调用透明度，而不只是聊天框。
- 真实 API 测试必须与默认自动测试分离，只从环境变量取 Key、使用人工短文本并脱敏输出。

## 本轮调研（前端统一美化）

- 阅读器已经成熟时，继续堆阅读功能的收益低于统一浏览、书库、设置和全局外壳的信息层级。
- 双皮肤应共享布局、组件、间距和状态结构，只改变色彩与氛围；否则会形成两套难以同步的产品。
- 桌面书库卡片应把“打开阅读”和“管理书籍”分离；运行任务状态是例外，不能为了卡片整洁被菜单隐藏。
- BrowserView/BrowserView-like原生层与Vue抽屉存在真实命中区域耦合；视觉改造必须保留并验证bounds避让。
- 设置长页适合分类侧栏，但分类切换应保留会话草稿且不改变显式保存语义。
- 美化验收不能只依赖build；至少要覆盖默认/最小窗口、明暗/品牌皮肤、键盘焦点和真实Electron点击区域。
- 即时可见且可逆的界面操作应静默；保存、删除、导出和持续任务结果才需要Toast或页面状态。
- 视觉方案也必须写死文案、空态、加载、长文本、减少动画和危险操作，否则导演仍需承担产品决策。

## 本轮调研（书库经营 2026-03-22）

- 阅读器多轮升级后，与 Koodo/Kindle 的阅读面差距小于书库经营（标签、元数据、查重）。
- 仓库已有搜索/排序/coverPath，顾问必须写清「扩展现有框」避免导演重做。
- 用户口头要书源市场时必须单问禁令，不能塞进书库战役。
- lastReadAt 能用 progress.updatedAt 就不要加契约字段。

## 本轮调研（下载体验 2026-03-22）

- 下载主路径已具备时，优化应补失败可见、速度档和离开页面后的进度，不要重写抓取。
- 进度事件只有计数时，结束清单必须把当次失败章放进同一事件，不能让页面再猜一次书库。
- 代表页未批准前，设置页和书库入口都算依赖页面，不能因为字段先落地就把界面铺开。

## 本轮调研（纸面界面 2026-03-22）

- 用户说按微信读书设计时，只取纸色正文、封面书架和底栏四项；书城、好友、划线和听书商城与本仓库禁令冲突，不能写进战役。
- 全局皮肤和正文纸色是两套控件。代表页只固定全局暖纸，正文纸色仍由底栏「背景」切换。
- 旧皮肤枚举存不下新三档时，必须先单问字段例外，不能假装不改契约。
