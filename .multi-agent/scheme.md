## 元信息

- 项目：小说浏览器（spbf）
- 确认日期：2026-03-22
- 选定方案：方向 A 纸面阅读
- 明确不选：方向 B 封面书架首页；方向 C 双栏书桌；保留夜樱为默认
- 阶段授权：先代表页
- 推进模式：W1 可做；W2 等代表页批准
- 市面关键来源：微信读书官方帮助「如何设置阅读界面的背景和字体」（weread.qq.com，2026-03-22 检索）；人人都是产品经理书架与阅读页拆解（2021-12-06，https://www.woshipm.com/evaluating/5237152.html）

## 一句话目标

使用者打开软件就看到上次那本书的暖纸正文；书架、浏览和设置换成同一纸面气质，下载与阅读能力不丢。

## 完成定义

1. 有阅读进度时，启动后主区是上次那本书的暖纸色正文，而不是四页同级大侧栏。没有书时主区是空书架，仍显示「还没有书」，并有去浏览的入口。
2. 阅读主区左侧是只含封面的窄书脊；底部是「目录」「进度」「背景」「字体」。顶栏有书名、书架、搜索、标记、朗读、AI、沉浸、浏览、设置。下载进行时顶栏显示书名和「已下 x / y 章」，并可取消。
3. 点书脊展开书架。封面能打开书。继续读、浏览下载一眼可见。检查更新、导入、导出、回收站、失败章仍能从书架管理到达。每本书现有的编辑、导出、删除入口仍在。
4. 浏览页仍能输入网址、打开、下载本书、配置本站规则，网页仍在内置视图。设置页外观是暖纸、白纸、夜间。已存 sakura 或 minimal 打开后显示暖纸。
5. 阅读页的搜索、标记、朗读、AI、沉浸仍可用，中文 aria-label 仍在。正文仍是纯文本。移入回收站、删除站点规则、恢复备份仍先确认。不新增快捷键，不新增点正文中间呼出工具栏。
6. 旧书不用重建。下载速度、API Key、站点规则、阅读进度仍在。断网、失败章、磁盘错误、取消、缺 Key、大章、同时只有一个下载的处置与现有文案不变，只改显示位置。

## 非目标

- 书城、好友、划线想法、听书商城
- 改抓取引擎、裸 fetch 下载、native 模块、依赖大版本升级
- 新增快捷键或点正文中间呼出工具栏
- 重建书库或改变章节正文格式
- 代表页确认前改书架、浏览、设置或去掉全局旧壳

## 选定理由

方向 A 把第一眼留给正文，同时用顶栏保住浏览和设置。B 会把首页改回书架，和已选的打开行为冲突。C 左右同屏，沉浸最弱。现有栈只改壳和皮肤取值，不换库。

## 默认体验（已拍板）

- 入口：扩现有四页，不新增路由页。打开有进度则主区直接是阅读；无书则空书架。
- 认可样板与可复用组件：无已认可样板。`.multi-agent/design/weread-ref/` 只是官方参考，不是样板。
- 布局：全窗暖纸。左书脊只有封面。中部正文。顶栏从左到右：书名、书架、搜索、标记、朗读、AI、沉浸、浏览、设置。底栏只有目录、进度、背景、字体。下载中才在顶栏加书名与「已下 x / y 章」和取消。
- 默认值：全局 skin=paper。正文纸色沿用用户已选的纸白、暖黄、柔灰或夜间；未选过则暖黄。下载速度、AI、站点规则默认不变。
- 空态：无书仍是「还没有书」，有去浏览入口。筛选无结果仍是「没有匹配的书」。无失败章仍是「没有失败章节」。无下载时不显示进度条。
- 加载中：浏览页沿用现有加载或停止。下载沿用现有进度，只改到顶栏。
- 错误提示：沿用现有文案与处置，不改规则。
- 成功反馈：沿用现有 toast 或静默，不新增大对话框。
- 破坏性操作确认：移入回收站、删除站点规则、恢复备份继续二次确认，文案沿用现在的。
- 快捷键：沿用现有，不新增。
- 文案语气：中文、简短、无樱花符号。
- 语言：只中文。
- UI 文本线框：

```text
[书名] [书架] [搜索][标记][朗读][AI][沉浸]     [浏览][设置]
下载中才加：已下 x / y 章 [取消]
[封面书脊]  暖纸正文
[目录] [进度] [背景] [字体]
```

点书脊展开书架，不占住章节目录。点背景只切正文纸色：纸白、暖黄、柔灰、夜间。点字体打开字体、字号、行距、列宽、段距、缩进、行焦点、滚动或翻页。这些项不删。

## 视觉探索与代表页

- 用户主要任务 / 第一眼信息：看书和下载同等重要；第一眼仍是上次正文。
- 喜欢 / 不喜欢 / 必须保留：要暖纸、工具不挡正文、去掉夜樱和大侧栏。必须留继续读、书架、浏览下载，以及现有阅读和管理能力。
- 候选预览与参考来源：用户已从方向 A、B、C 选定 A。参考图 `.multi-agent/design/weread-ref/toolbar.png`、`bg1.png`、`font1.png`，来自微信读书官方帮助。
- 推荐方向与理由 / 用户反馈：用户选定 A。
- 设计委托范围：纸面方向内的对齐、间距、字号层级、圆角、普通辅助文案。不得删功能、改核心操作、数据策略或技术栈。
- 代表页与对应切片：W1.2 阅读页。全窗固定暖纸，不放全局三档切换。
- 状态：待代表页
- 批准证据：无。待用户看实际窗口后的确认。
- 后续页面依赖：W2.1 书架、W2.2 浏览、W2.3 设置、W2.4 去旧壳，全部依赖 W1.2 批准。
- 原型数据：代表页用现有书库。没有书时用空态，不用假书冒充已下载。
- 验收：功能与视觉分开。代表页截图绑定 commit、窗口尺寸和有书状态。无截图不得把视觉判为通过。

## 技术约束（必须遵守）

- Electron + electron-vite + Vue 3 + TypeScript + Naive UI
- 浏览与下载共用 persist:novel
- 下载用隐藏 webContents 逐章 loadURL，禁止裸 fetch 当下书主路径
- 无 native 模块
- 章节正文只渲染纯文本，禁止 v-html

## 逐刀实现说明（已拍板）

### W1.1

- 改什么：Skin 类型、默认值和 settings 读入。旧 sakura、minimal 都变成 paper。
- 不改什么：preload、IPC 名、下载、书库、AI、阅读进度字段。
- 关键分支：缺省、paper、white、night、两种旧值。未知字符串按 paper，不抛到界面崩溃。
- 完成时在界面或磁盘上能看到：旧皮肤不会阻止启动；契约测试通过。此刀无新界面控件。

### W1.2

- 改什么：阅读页布局为线框。顶栏图标保留搜索、标记、朗读、AI、沉浸。底栏四项。书脊只放当前书封面。全窗固定暖纸。
- 不改什么：正文渲染、快捷键、点正文中间的行为、全局三档、书架页、浏览页、设置页的业务。
- 关键分支：有书、无书时空书架、下载中顶栏、目录空、四种正文纸色。
- 完成时在界面或磁盘上能看到：实际窗口符合线框，并有绑定 commit 的截图。

### W2.1

- 改什么：书架改为封面入口，从书脊展开。管理收进明确入口。
- 不改什么：导入导出格式、回收站规则、检查更新和失败章规则。
- 关键分支：空书架、有书、筛选无结果、回收站。
- 完成时在界面或磁盘上能看到：封面打开原书；管理项都能到达。

### W2.2

- 改什么：浏览页视觉进入纸面壳。
- 不改什么：地址打开、下载本书、站点规则、内置网页视图、下载状态机。
- 关键分支：加载中、下载中、失败清单、无失败章。
- 完成时在界面或磁盘上能看到：上述操作仍可走通。

### W2.3

- 改什么：设置外观三项和写入的 skin 值。
- 不改什么：书库路径、下载速度、AI、站点规则、备份恢复的行为与确认。
- 关键分支：首次旧值、切换三项、重启。
- 完成时在界面或磁盘上能看到：设置页文字是暖纸、白纸、夜间；磁盘中的 skin 是 paper、white 或 night。

### W2.4

- 改什么：去掉旧侧栏壳和夜樱装饰，让四页共用纸面壳。
- 不改什么：W1.2 已批准的阅读层级，除非为了去掉旧壳必须等比例搬移。
- 关键分支：四页切换、下载中顶栏、无下载。
- 完成时在界面或磁盘上能看到：没有夜樱文案，没有旧的四页大侧栏。
