# 真实书籍翻页：84°–91° 竖缝观察报告（2026-11-10）

翻页中态一度读成「纸先被撕开一条再翻页」。根因不是几何，而是**内容透明度对投影宽度的判据太松**：
正面正文淡到下限、纸背又要转过 90° 才起淡，中间那段角域里被压成十几像素宽的竖带仍留着 36%
不透明度的字，读起来就是撕页。

修复引入 `flipContentSideFalloff`（`src/renderer/pages/realBookFlip.ts`），按投影宽度 `|cos θ|` 判定：
`≥ 0.72`（约 44° 以内）满可见、`≤ 0.55`（约 57°–123°）收到 0、中间用 smootherstep 一阶连续过渡。
正背共用同一系数，90° 换面点两侧同为 0，不会出现一面有字一面没字的硬切缝。

本报告记录该修复在**实机**上的复核：命中测试 + 亮度剖面两套判据，外加可复算的墨迹密度。

**数据来源**：本报告的全部数值来自 `docs/img/realbook-flip-seam-2026-11-10-run.log`（当前一轮）。
同目录的 `...-run.log.bak-20261111-010310` 是更早一轮的归档，**不与本轮数据混用**。

## 复现方式

完整步骤（含旧日志归档、哈希核对、Git 归档）见 `docs/realbook-flip-seam-repro.md`。最小流程：

```powershell
node node_modules/electron-vite/bin/electron-vite.js build
$env:SPBF_SLOW_FLIP='1'
$env:SPBF_KEEP_SHOTS='1'
node scripts/realbook-flip-fps-e2e.mjs
node scripts/realbook-flip-ink-density.mjs
```

`SPBF_SLOW_FLIP=1` 把翻页放慢 10 倍，并把组件用的 `performance.now` 钉在指定进度上逐帧定格。
定格进度来自 `scripts/realbook-flip-fps-e2e.mjs` 的 `frames = [0.45, 0.48, 0.5, 0.52]`。

**帧序 ↔ 进度映射的唯一权威来源就是这个常量**（截图名 `realbook-flip-${index+1}.png` 由它派生）。
日志里不打印 t 值，所以本报告的 t 全部来自脚本常量，不是日志实测。

## 采样锚点：斜带的真实 3D 边

竖带是绕左轴转过的平面。`getBoundingClientRect()` 给出的是投影后的**包围盒**，它的右缘与相邻两条带
共享的那条 3D 边不是同一个位置——早先版本的剖面因此量到无关像素，结论不可用。

现在的锚点做法：在每条带的自身右缘、三个高度（页高 32% / 50% / 68%）各放一个零尺寸探针元素，
由浏览器沿 `rotateY(angle)`、sheet 的 `rotateX/rotateZ`、以及 `perspective(1750px)` 自己投影，
再读探针的屏幕坐标。逐行取样是必需的：同一条边在 y=243 与 y=479 上屏幕 x 相差约 6–12px
（见下表三行区间）。

只把「带 i → 带 i+1」这类带与带之间的边纳入判据：
- 最外带的右缘排除——`.real-book-flip-slice.is-outer::after` 是刻意的纸边受光亮线，量它必然误判；
- 靠近边心 ±2.5 CSS px 的抗锯齿列不计入判据统计（相邻带 `width + 0.5px` 的故意搭接过渡区）。

## 判据

采样窗口：边心 x 左右各 7 CSS px（`width: 15, scale: 2` → 30 设备像素），纵向取 60 CSS px 窄条，
逐列求**亮度中位数**（Rec.709 加权：`0.2126R + 0.7152G + 0.0722B`，作用在 sRGB 编码值上）。

取中位数而不是单行均值，是因为窗口只有 ±7px，正文笔画必然落在里面：单行会被笔画砸出 20–80/255 的
坑，那是字不是缝。真正的竖缝是贯穿页高的一条暗线——一列在所有行上都暗，中位数不受笔画影响。

**判据（16/255 是主阈值，8/255 仅作参考）**

- 主判据：窗口内不存在「局部极小且比两侧较暗者低 > 16/255」的列（凹陷深度）。
- 辅助判据：窗口最低亮度不得接近桌面参考亮度（`< 桌面 + 30` 即判为漏桌）。
- 台阶（边两侧远场均值差）**只作为参考输出，不参与判定**：两张纸的明暗本来就不同，跨接缝出现
  10–20/255 的台阶是正常的纸面梯度，不是缝。早期版本把它当判据曾把 12 条正常边误判为失败。

## 墨迹密度（可复算）

由 `scripts/realbook-flip-ink-density.mjs` 产出，原始输出在
`docs/img/realbook-flip-seam-2026-11-10-ink.txt`。固定口径（见脚本 `L20-L40`、`L120-L137`）：
Rec.709 加权亮度 `0.2126R + 0.7152G + 0.0722B < 170` 记为墨迹，`2px` 步长采样（x、y 同一步长，
分母 = 区域实际采样像素数），百分比按 `Math.round((1000 * ink) / total) / 10` 保留一位小数。
竖带区域取该帧三行命中区间的并集（`y 60..620`；帧 1 `x 694..812`、帧 2 `x 615..730`、
帧 3 `x 523..704`、帧 4 `x 446..698`，含纸边暗部与阴影），正文区取右页 `x 760..1180, y 95..560`。

判据是上面的角域与亮度剖面。

## 结论

- 命中测试：四帧的纸面区间内部漏列数全为 0（12 个采样行），三帧实际覆盖 84°–91° 角域（命中条带数依次为 2 / 2 / 1 / 0）。
- 逐带可见度：84°–91° 覆盖到的所有带子内容 opacity 均为 0，纸面只剩纸色、纸边与阴影。
- 亮度剖面：三帧共 21 条边-行样本，最深深陷 **0.6/255**，窗口最低亮度 **209/255**，
  桌面参考 43.7/255，**没有任何一列接近漏桌**。
- 两套判据一致：84°–91° 的接缝上有明暗台阶（**0–20.8/255**，纸面光影差异），但没有凹下去的缝。
- 脚本整轮结果：`28 项通过，0 项失败`（慢动作模式下帧率判定被跳过，只保留视觉与几何判据）。

### 关于帧 4 的纸背正文（不计入验收）

帧 4 的 `#8–#11` 位于 **124.9°–132.5°**，纸背内容可见度依次 **0.049 / 0.279 / 0.574 / 0.831**（最高 **b=0.831**）。
这些带全部超出 84°–91° 判据域：它们是纸背转到快平时正常起淡的那一段，图上确实能看到正文，
按本报告的判据口径不计入 84°–91° seam 验收，也不算失败样本。

## 已知局限

1. **新旧两轮不同源**。`...-run.log.bak-20261111-010310` 是更早一轮（命中角度 84.1/88.2、84.7/89.4、
   88.2、空集），本轮是 85.3/89.4、86.0/90.6、89.4、空集。同一 `frames` 常量下条带角度相差零点几度，
   是定格时刻与实际渲染帧对齐的抖动；本报告只用本轮数据，不与归档轮混写。
2. **归档日志的编码**。脚本输出经 PowerShell 重定向落盘时是 UTF-16LE；归档到 `docs/img/` 的
   `...-run.log` 已转成 UTF-8（内容逐行未改）。复核时若看到乱码，请确认打开的是归档这份。
3. **t=0.52 帧的靶边是空集**：该帧所有带子都在 91° 以上，不在本题角域内。它证明的是「纸已转过去之后
   也没有竖缝」，不是 84°–91° 交接处的证据——请勿把这一帧计入角域结论。
4. **日志不含 t 值**：帧序与 t 的对应关系来自脚本常量 `frames`，报告中已注明，不属于实测。
5. **亮度取的是 sRGB 编码值上的 Rec.709 加权**，不是线性光亮度。8/255 与 16/255 两个阈值是在同一口径下
   标定的，跨口径比较无意义。
6. **判据口径与本轮开工时的写法有出入，需单独对待**。开工时定的是「边两侧远场均值差 < 8/255 且无单列
   偏离 > 16/255」。实测发现「两侧均值差」根本不是缝的判据：两张纸的明暗本来就不同，跨接缝出现
   10–20/255 的台阶是正常的纸面梯度，直接套会在 21 条正常边上判出 12 条「有问题」。现判据换成
   「凹陷深度 ≤ 16/255 且不漏桌」，16/255 仍是主阈值，8/255 降为仅作参考输出。这是判据的实质变更，
   **不是**原先那两条口径下的通过。若需要严格沿用旧口径，请把它当作「旧口径不适用」的证据读。
7. **墨迹密度的坐标是人工选定的**（三行命中区间的并集 + 右页正文框），不是自动分割。它能稳定复现
   （同图同坐标同阈值必得同一结果），但换一个框选范围数值会变；比较不同轮次时请用同一版脚本。
8. **未覆盖**：本报告只验证 0.45–0.52 这段角域与当前构建。不同视口宽度、不同 `BEND_DEG`、
   以及纸背正文内容较密（例如满页小字）时的观感未单独复核。
