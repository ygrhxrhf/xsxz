# 小说浏览器（spbf v0.1.0）真实用户体验验收报告

- 验收日期：2026-10-15
- 验收对象：打包版 `release/win-unpacked/小说浏览器.exe`（非 `npm run dev`）
- 验收方式：真实运行打包应用，实际操作界面（地址栏、按钮、抽屉、原生对话框），配合 Chromium 远程调试端口读取真实 DOM 与样式；AI 走本地 mock 服务，不联网、不使用真实密钥
- 环境：Windows、Node v24.20.0、默认书库路径 `D:\spbf\library`
- 结论：**核心链路（浏览 → 下载 → 书库 → 阅读 → 设置 → AI）全部跑通，可用性达标**；发现 1 个阻塞级、2 个中等级、4 个轻微级问题，详见下节

---

## 一、问题清单

### F1【阻塞 / 严重】目标盘不存在时，应用启动即失败，无窗口、无任何提示

- 复现：机器上没有 D 盘（默认书库路径 `D:\spbf\library` 所在盘不存在），双击启动应用。
- 现象：进程起来了，但**没有任何窗口**，任务管理器里只有一堆同名进程。用户视角就是「点了没反应」。
- 后台日志：`mkdir '\\?'` 抛错，并以 `UnhandledPromiseRejection` 结束启动流程。
- 影响：这是**第一次启动就会踩到**的场景（新机器、只有 C 盘的机器、U 盘/网络盘环境）。用户不会去看日志，只会认为软件是坏的，且没有任何自救路径。
- 建议：启动时若书库路径不可写/盘不存在，弹出一个可操作的窗口，明确告知「默认书库 D:\spbf\library 不可用」，并提供「换一个目录」的入口（复用设置页的「选择目录」），而不是静默失败。至少也要 `dialog.showErrorBox` 把原因说清楚。

> 后续变更（2026-10-16）：默认书库路径已从 `D:\spbf\library` 改为当前用户家目录下的 `spbf\library`，因此「机器没有 D 盘 → 双击启动」这条复现路径不再触发本问题。启动兜底（目录不可用时弹窗说明并当场换目录）照旧保留，用于任何不存在或不可写的手工配置路径；其逻辑已抽出为 `src/main/startupGuard.ts` 并有 6 条聚焦测试。

### F2【中等】OCR 语言包加载失败，但界面仍宣称「本机 OCR 引擎可用」

- 现象：运行日志报 `Failed loading language 'ǎ8'` / 找不到 `./ǎ8traineddata`。安装包内实际是 `resources/resources/chi_sim.traineddata.gz`、`eng.traineddata.gz`（gzip 压缩包）。
- 影响：设置 → 站点规则里写着「本机 OCR 引擎可用（tesseract.js，离线识别）」，勾选「图片/字形走 OCR」后**实际无法识别**。用户按界面文案做了决策，功能却不可用，且错误信息（`ǎ8traineddata`）对用户毫无意义。
- 建议：修正语言包解压/路径查找逻辑；在引擎不可用时把设置页文案改为明确的不可用状态与原因，而不是静态宣称可用。

> 后续变更（2026-10-16）：有了更深的发现，两处都已修。
> 一、原来的查找逻辑根本没传 `gzip: true`，而包里是 `.traineddata.gz`，tesseract.js 按这个开关决定文件名后缀 → 它一直去找不存在的 `.traineddata`。
> 二、更隐蔽的是：本机 tesseract.js 7 + 随包 core 一次加载**两种语言**（`chi_sim+eng`）时，核心会拿一个乱码语言名去开表（`Failed loading language '玂'`）并静默失败，而 `createWorker` 不抛错（内部 `.catch(() => {})` 吞掉了初始化异常）——所以「语言包文件存在」并不等于「引擎可用」，界面会谎报可用。现在改为**只加载 `chi_sim` 一个语言**，并让 `ocrEngineReady()` 额外核对引擎虚拟 FS 里是否真的有该语言包（磁盘上有 ≠ 引擎里吃进去了）。
> 护栏：`src/main/ocrEngine.integration.test.ts` 真跑一次引擎；`npm run e2e:startup` 断言真实进程 stderr 里不再出现语言加载失败。

### F3【中等】导入 epub 时把 `<head><title>` 的文本混进正文，导致章节标题重复

- 复现：书库 → 导入 txt / epub → 选 `fixtures/sample.epub`（该文件 `<head><title>第一章 启程</title>` 与 `<h2>第一章 启程</h2>` 同时存在）。
- 现象：导入后章节正文开头多出两行重复标题，阅读器里肉眼可见：

  ```
  第一章 启程          ← 目录/标题
  第一章 启程          ← 正文第一行（来自 <head><title>）
  从此段朗读
  第一章 启程          ← 正文第二行（来自 <h2>）
  清晨的雾还没有散尽。…
  ```

- 连带影响：导出 txt 与导出 epub 都会把这层重复**固化**进产物（导出的 `ch0001.xhtml` 里 `<p>第一章 启程</p>` 出现两次），错误会随导出扩散。
- 根因位置：`src/main/importEpub.ts` 的 `stripXhtml()`——它把块级标签换成换行、其余标签直接删掉，`<head>` 里的 `<title>` 文本因此作为普通文本保留下来。该文件目前也没有对应测试。
- 建议：解析时丢弃 `<head>`、`<script>`、`<style>` 子树，只取 `<body>`；并补一条导入测试锁住该行为。

### F4【轻微 / 体验】导出与备份的目录选择框：标题错位、且不提供「新建文件夹」

- 现象一：点「导出 txt / 导出 epub / 备份书库…」弹出的原生对话框标题是「**选择书库目录**」。用户是在选**导出/备份的目标目录**，标题却写着「书库目录」，容易误解为要改动书库位置。
- 现象二：路径不存在时，只弹出「路径不存在。请检查路径是否正确，然后重试。」，**没有任何新建目录的引导**。用户必须自己切到资源管理器建好目录再回来重选。
- 建议：标题按用途区分（如「选择导出目录」「选择备份目录」）；在错误提示里给出「是否现在新建该文件夹」或至少提示「请先在文件管理器中创建该目录」。系统选择器本身是带「新建文件夹」的，但错误路径下用户看不到可操作的下一步。

### F5【轻微 / 体验】去广告按钮的文案是「动作」而不是「状态」

- 现象：按钮文案在「关闭去广告」与「开启去广告」之间切换，用户看到「关闭去广告」时无法立刻判断**当前是开还是关**。
- 建议：改为状态式文案（如「去广告：已开启」）或直接做成开关控件。

### F6【轻微 / 体验】书库「全部检查更新」的进度抽屉没有「关闭」按钮

- 现象：进度面板（含失败章节列表）只能点右上角的小叉关闭，面板内没有「关闭」按钮；同页的「回收站」弹窗是有「关闭」的，两者不一致。
- 建议：补一个「关闭」按钮，与其他弹层保持一致。

### F7【轻微 / 体验】阅读器工具栏默认隐藏且只有图标，缺少可见标签

- 现象：进入阅读器后顶部工具栏是自动隐藏的，鼠标移入才出现；出现后按钮也多为纯图标（依赖 `aria-label`），新用户不易发现「搜索 / 标记 / 朗读 / AI」这些能力。
- 建议：首次进入给一次轻量提示（或首屏保持工具栏可见几秒）；关键入口补文字标签。

## 二、已验证通过的功能（逐项实测）

### 浏览页
- 地址栏输入网址 → 点「打开」正常加载；点章节链接后地址栏与页面同步。
- 更多工具菜单完整：配置本站规则 / 去广告开关 / 缩小、放大网页 / 100% / 网页查找 / 点选隐藏 / 撤销隐藏 / 下载进度。
- 「配置本站规则」正确跳转设置页并预填当前域名。
- 阅读模式可用：返回、目录、自动、听书、加书架、排版，以及段落级「从此段朗读」。
- 编码处理：无 charset 的页面会**复现乱码**，但点「下载本书」时给出的是可读的中文提示「页面编码可能不正确，正文疑似乱码，未开始下载。请先刷新页面…」并提供「刷新页面」按钮——**这一点比旧版评审记录的误导性提示有明显改善**；GBK 站点中文显示正常。

### 下载本书
- 「下载前预览」展示书名、作者、目录章数与样本正文；「确认下载这本书」后进入「下载进度」。
- 进度面板显示百分比、已下章数、当前章节、失败数与失败原因；「取消下载」可用。
- 失败章节处理闭环：失败清单 →「只补失败章」→ 补下成功（实测 6 章站点：首轮 5/6，补下后第 6 章成功）。
- 失败原因分类准确：HTTP 500 记为「章节地址加载失败：HTTP 500」。
- **付费墙自动解锁生效**：站点把正文放在 `display:none` 的隐藏节点里，应用自动找回正文并入库，同时提示「质量检查发现 1 项疑似问题，可到书库核对」——既有能力也有提醒，体验良好。

### 书库
- 列表/卡片、搜索框、状态筛选、最近读过、网页书架（刷新目录 / 移除）均正常。
- 卡片「更多」菜单：编辑信息（改名即时生效并有「已保存」提示）、检查质量、检查更新、重试失败章、查看失败章、导出 txt、导出 epub、移入回收站。
- 导入 txt（CRLF 与纯 LF 两种）分段均正确——**旧版评审记录的「CRLF 段落合并」未复现**。
- 导出 txt / 导出 epub 均能落盘（epub 内含 container.xml、content.opf、toc.ncx 与分章 xhtml，结构正确）。
- 回收站完整闭环：移入回收站 → 回收站内显示书名/章数/删除时间/占用空间 → 还原 → 彻底清除（带「此操作不可撤销」二次确认）→ 清空后显示「回收站是空的」，并提示「超过 30 天的条目会在下次启动时自动清理」。
- 「全部检查更新」：进度（正在检查 2/2）、结果（已下 5 / 6 章 · 1 失败）、逐章失败原因、失败章节清单与「只补失败章」「打开这本书」。
- 备份与恢复：备份生成 zip（实测 38 个条目，含 book.json 与分章 json）；从备份恢复返回成功，书库状态与备份时一致（含「整库覆盖」语义与失败保留原库的说明文案）。

### 阅读器
- 目录（含过滤、当前章标记）、进度（全书约 % · 本章 % · 还剩章数）、背景（纸白/暖黄/柔灰/夜间）、字体（字体/字号/行距/列宽/段间距/首行缩进/行焦点/阅读方式/恢复默认）四个面板齐全。
- **主题切换实测生效**：切「夜间」后正文容器背景由 `rgb(255,255,255)` 变为 `rgb(27,29,32)`，文字色同步变为 `rgb(216,210,199)`，选择状态持久化。
- 听书（TTS）：系统语音/在线语音、系统音色枚举、语速、自动下一章、定时停止；实测播放可用（出现「上一段 / 暂停 / 下一段 / 停止 · 本章第 N / 4 段」）。
- 本书内搜索：输入关键词后返回命中章节与上下文片段。
- 标记：给本章加书签 / 移除本章书签（带二次确认），支持备注与划线。
- 翻章与进度持久化：点「下一章」后正文与进度同步；已存进度落盘（`chapterId` + `scrollRatio` + 时间戳）。
- 沉浸模式可进入/退出。
- 快捷键说明面板完整（←/→、Space/J/K、T/A/R、I/N、M/Alt/Esc、Ctrl+F、+/-）。
- AI 面板：清正文（发送前展示预算、目标段落与固定规则，可「应用到正文」/「关闭」）、AI 助手（前情 / 记忆 / 问答 / 笔记 / 输出，含 token 用量与月度额度显示）、聊书入口。
- **AI 真实调用验证**（本地 OpenAI 兼容 mock，走流式）：连接测试返回成功；「生成本章摘要」成功并回写 token 用量（输入 120 / 输出 60）；「建立已读剧情记忆」正常进入「人物与伏笔时间线」并提示摘要覆盖情况。前情生成对返回长度有 400–600 字的硬校验，mock 返回过短时给出明确错误「前情提要长度不符合 400–600 字要求，原有前情未改变」——**校验与保护行为正确**。

### 设置页
- 七个分区：外观 / 书库 / 听书 / AI / 站点规则 / 备份与恢复 / 关于。
- 外观：浅色 / 深色切换，实测切深色后 `spbf.skin` 持久化为 `dark`。
- 书库：路径选择、保存路径、搬迁书库，并说明「保存路径只切换以后新写入的位置，不复制已有书库」。
- 听书：在线语音接口地址 / 模型 / 音色 / Key、连接试音，并明确提示「当前正文片段会发送到你填写的服务地址，可能产生费用」。
- AI：模型服务、接口地址、模型名、API Key、独立向量服务、思考模式、自动概览、自动整理、单次输入提醒阈值、每书每月额度、保存 / 测试连接；未配置时明确显示「未配置 API Key，AI 功能不可用」。
- **自定义服务有安全闸门**：指向非 DeepSeek 的接口地址时，测试连接会先要求确认「API Key 和你主动选择的正文内容将发送到此接口地址。请只使用你信任的服务。」，确认信任后连接成功——隐私保护到位。
- 站点规则：域名、书名/作者/目录/正文选择器、正文噪音正则（说明「最多 20 条，非法正则会被忽略」）、上一章/下一章选择器、解锁容器选择器、章节接口与 POST 体、付费墙自动解锁开关、图片/字形 OCR 开关。
- 备份与恢复：说明文案准确（「备份把整个书库（不含回收站）打包成 zip…恢复是整库覆盖：先校验并准备备份，切换失败时自动还原原书库」），每周自动备份（仅保留最近五份自动备份）。
- 关于：显示版本、当前书库路径与技术栈。

## 三、总体评价

优点集中在**「说人话」的错误处理**与**数据安全**上：乱码站点会在下载前拦下并解释原因、付费墙能自动找回正文并提示质量核对、备份恢复明确承诺「失败时保留原书库」、自定义 AI 服务有信任确认、前情长度不合规时保留原有内容不覆盖。这些都超出同类工具的平均水准。

需要优先修的是 **F1**：它出现在用户与产品的第一次接触点，且没有任何补救路径。**F2、F3** 属于「界面承诺了但实际没做到」，会让用户对准确性失去信任。F4–F7 是打磨项。

## 四、验收方式说明

- 全程使用打包版真实界面操作，未修改任何产品代码。
- 因桌面自动化会话多次中断，原生文件对话框（导入 / 导出 / 备份 / 恢复）通过 Win32 窗口枚举 + UI Automation 检查与驱动；界面交互通过 Chromium 远程调试端口在真实渲染进程上完成，读取的是真实 DOM 与计算样式。
- 所有涉及网络的功能均指向本机 fixture 站点与 mock AI 服务（端口 5180/5181/5182/5183/18080/18081），不联网。
- 部分结论经 fixture 修正后复测：初次出现的「正文为空或过短」「付费墙未解锁」「AI 未返回有效内容」均为测试桩不满足产品阈值/协议所致（正文长度阈值、隐藏节点增量判据、流式 SSE），修正测试桩后复测通过，不计为产品缺陷。
