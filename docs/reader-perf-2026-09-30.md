# 阅读器一万段真实页面复核

在 Electron 43 的 Linux 开发环境中测量；测试输入由 `node scripts/reader-perf-fixture.mjs` 生成到系统临时目录，不接触现有书库。构建后把输出的 `configRoot` 设为 `XDG_CONFIG_HOME`（Windows 为 `APPDATA`），再启动 Electron。使用 Chromium DevTools Protocol 观察 `PerformanceObserver` 的 `longtask` 条目及页面操作耗时。

| 场景 | 改动前 | 改动后 |
|---|---:|---:|
| 一万段首次挂载最大长任务 | 655 ms | 92 ms |
| 一万段完整呈现 | 约 1.0 s，但页面不能滚动 | 约 5.1 s，分批呈现且可滚动 |
| 滚动到中间并完成两帧 | 无效，容器不能滚动 | 约 50 ms |
| 搜索框输入并完成一帧 | 约 399 ms，长任务 371 ms | 约 130 ms，最长任务 115 ms |
| 选区弹出工具条 | 未测 | 约 130 ms，最长任务 74 ms |
| 切到下一章 | 未测 | 约 27 ms |

改动后：主内容容器高度受窗口约束；一万段按每批 120 段挂载，并仅对大章启用 `content-visibility`。搜索高亮限制在当前位置附近，书内搜索结果仍扫描整章。完整呈现需要数秒，但期间主线程没有超过 200 ms 的长任务。

在 1100×720、1366×768、1920×1080 的视口下，页面没有横向溢出。沉浸模式静置后顶栏和底栏透明度为 0，Alt 唤回后为 1，细进度条始终可见。把第 5000 段滚到视口上方并保存，字号改为 26、列宽改为窄档后重开，恢复位置落在第 4997 段；偏差小于一屏。上述时间受机器性能影响，Windows 安装包仍需在目标系统手测。
