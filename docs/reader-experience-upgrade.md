# 阅读模块体验升级方案

状态：R0～R2 已实施并完成 Linux Electron 复核（2026-09-30）；下文保留实施前的决策依据。  
适用项目：spbf 小说浏览器（Electron + Vue 3、纯文本章节）  
范围依据：`AGENTS.md`；现状依据：当前 `Reader.vue`、阅读辅助模块、共享类型与设置实现。

实施结果：工具层显隐已接到界面，键盘焦点与弹层期间保持可用；大章采用分批挂载和按需布局，实测最长主线程任务从 655 ms 降至 92 ms；进度增加可选段落锚点并保留比例回退。实测数据和隔离样本见 [阅读器一万段真实页面复核](reader-perf-2026-09-30.md)。下文“当前主要问题”和“分阶段实施”记录当时发现的问题与原计划。

## 1. 结论

当前阅读器已具备这套体验的主要功能，下一步目标是让工具显隐真正落到界面：

> **连续滚动为主，屏幕翻页为辅；正文居中，工具按需显现；AI、标记、搜索通过工具栏和抽屉进入。**

下一轮先把沉浸显隐状态接到实际界面，再用真实 Electron 页面验证大章性能与跨排版设置的进度恢复。四主题、列宽、阅读方式和章节预读已有实现，不再列为新增任务。CSS 多栏真分页仅在现有屏幕翻页无法满足实际使用时评估。

## 2. 当前模块判断

### 已实现的基线

- **导航与进度**：目录过滤与定位、上下章、失败章提示与重试、章末下一章卡片、书末返回书库；章内进度按可滚动距离保存和恢复，底部展示全书与本章两条进度线。全书百分比目前按章节等权估算。
- **阅读偏好**：纸白、暖黄、柔灰、夜间四主题；字体、字号、行距、窄中宽列宽、段间距、首行缩进、按段落聚焦和连续滚动 / 屏幕翻页。偏好经 `settings.get/set` 保存，旧 `nightMode` 值由设置归一化逻辑迁移。
- **阅读交互**：边缘换章热区、可视页翻屏、目录状态标签、书内搜索、书签、划线和备注；选区工具条提供复制、划线、备注、翻译、问 AI，并按选区定位。
- **辅助能力**：相邻已下载章节空闲预读、TTS 从指定段开始朗读、快捷键提示和减少动态效果支持；AI 清正文、前情摘要、人物记忆和已读内容问答已有入口。

因此后续工作应修复现有体验缺口并验证边界场景，避免重复实现已交付功能。

### 当前主要问题

1. **沉浸显隐尚未作用到界面**  
   `Reader.vue` 中 `toolsVisible` 已按静置、鼠标、Alt 和沉浸模式更新，但模板和样式未使用该状态。顶部工具栏、底部四按钮栏仍常驻；现有 `immersive-locked` 样式仅确保细进度条可见。应先恢复真实显隐，再处理键盘焦点与弹层可用性。

2. **大章性能缺少真实渲染证据**  
   当前 `renderedParas` 全量映射，模板对每段执行 `v-for`。`readerPerf.ts` 的一万段样本覆盖分段与文本装饰开销，未包含 Vue 挂载、DOM、搜索定位、划线和滚动交互。尚不能据此断言需要虚拟段落，也不能据此判定真实大章已通过。

3. **进度恢复仍依赖滚动比例**  
   章末 100% 的计算已经修正；但字号、列宽、窗口大小或清正文改变内容高度后，同一比例未必对应同一段文字。需要实测恢复误差，再决定是否增加段落锚点。

4. **全书进度是章节等权估算**  
   `approximateBookRatio` 用章节序号和当前章比例计算全书百分比。章节长度差异很大时，它表示章节位置，不等同于已读文字占比；应验证用户是否需要更精确的进度，或把“估算”含义标清。

## 3. 外部方案中值得借鉴的部分

### Readium：把阅读偏好当成完整系统

Readium 的 EPUB 导航器把字体、字号、行距、段间距、首行缩进、页边距、文本对齐、滚动/分页等作为相互关联的阅读偏好，而不是只有字号和夜间模式。

参考：<https://readium.org/kotlin-toolkit/3.3.0/guides/navigator/preferences>

### Microsoft 沉浸式阅读：减少干扰比增加功能更重要

Microsoft Immersive Reader 提供列宽、文字间距、页面主题、朗读和 1/3/5 行焦点模式。对本项目最有价值的是“列宽 + 主题 + 行焦点 + 朗读联动”。

参考：<https://support.microsoft.com/en-us/education/learning-accelerators/use-immersive-reader-in-microsoft-edge-1>

### W3C：可调文字间距、对比度和键盘焦点

阅读设置不能只追求好看，还要保证用户放大文字、增加间距后内容仍然可读；交互控件应有清晰的键盘焦点和足够对比度。

参考：

- <https://www.w3.org/WAI/WCAG21/Understanding/text-spacing>
- <https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum>
- <https://www.w3.org/WAI/WCAG21/Understanding/non-text-contrast.html>

### 中文排版：行长应比拉丁文字更短

中文正文建议以约 30～40 个汉字一行为目标，行高通常在 1.5～2.0 之间更舒适。项目当前默认行高 1.8，正文已有三档列宽；下一步应在实际窗口与字体组合下核验行长。

参考：

- <https://www.morisawa-usa.com/post/simplified-chinese-typography-basics>
- <https://chenhuijing.com/blog/chinese-web-typography>

## 4. 现有界面与目标状态

### 4.1 阅读主界面

当前页面已有中央正文纸张、左侧书脊、顶部工具栏、底部“目录 / 进度 / 背景 / 字体”栏和双层细进度条。目标是在保留这些操作入口的前提下，让阅读时的工具层按现有静置和沉浸状态真正淡出；正文与进度条仍可见。弹层打开、选区操作或键盘焦点位于工具内时，不应让工具突然消失。

### 4.2 工具分工

- 顶部保留书名、书架、搜索、标记、朗读、AI、浏览、设置和沉浸入口。
- 底部保留目录、进度、背景、字体四入口；展开后显示相应面板。
- 显隐修复只调整呈现与唤回，不改变按钮含义、快捷键或已有功能。

### 4.3 正文与外观

当前默认字号 18px、行高 1.8、宋体阅读、首行缩进 2em、段间距 0.45em；列宽以 `em` 为单位，有窄 / 中 / 宽三档。四主题、字体、字号、行距、列宽、段落设置、按段落聚焦及阅读方式均已有设置和持久化。连续滚动模式按一屏约 90% 翻屏；屏幕翻页模式按可视页定位，并非 CSS 多栏分页。

后续只在实际屏幕上核验默认行长、对比度和不同字号下的可读性；不重复增加 `ReaderPrefs` 字段。

### 4.4 章节、选区与 AI

边缘换章热区、章末下一章卡片、书末返回书库、目录定位与“未下 / 失败 / 空 / 当前 / 已读”状态已存在。选区工具条按选区矩形定位，提供复制、划线、备注、翻译和问 AI；滚动后关闭。AI 通过顶部入口、选区操作和抽屉按需出现。这些路径是后续显隐与性能改动必须保留的回归基线。

## 5. 分阶段实施

原方案的进度公式、四主题、排版偏好、可视页翻屏、预读、目录状态、选区工具和快捷键已落地，不能再作为待开发阶段。以下阶段只列当前仍需完成或验证的工作。

### R0：修复沉浸显隐（优先实施）

目标：让现有 `toolsVisible` 状态控制顶部和底部工具层，保持正文、书脊和细进度条的可读性；不改 IPC、共享类型或磁盘格式。

1. 将静置隐藏、鼠标靠近、Alt 临时唤回和 M 沉浸锁定的状态接到实际界面，避免隐藏后占位或正文跳动。
2. 弹层、选区工具条、TTS 控件或键盘焦点活动期间保持所需入口可用；Esc 仍优先关闭当前弹层。
3. 保留顶栏与底栏现有分工、按钮语义、快捷键和减少动态效果设置。

验收：在 1100×720、1366×768、1920×1080 下，静置后工具确实淡出，唤回后可用；仅用键盘可打开目录、调整外观、翻屏、换章和退出沉浸；弹层不被定时隐藏，进度线始终可见。

### R1：真实大章性能复核（R0 后）

目标：先取得 Electron 页面中的实际渲染和交互数据，再决定是否改变渲染策略。

1. 用隔离书库加载约一万段的合成章节，记录首次显示、连续滚动、搜索、划线、可视页翻屏和换章时的耗时与长任务。
2. 保留 `readerPerf.ts` 的文本处理基准，但单独记录 Vue 挂载与 DOM 更新；不能把文本装饰耗时当成整页性能结论。
3. 仅在真实页面达到预先记录的卡顿门槛时，实施分批挂载或可见段落渲染，并验证搜索定位、标记坐标、TTS 跟读和进度恢复。

验收：保留可复查的测试输入与性能数据；普通章节无退化。若触发优化，异常大章持续滚动、搜索和换章不出现明显主线程冻结，且正文仍只按纯文本渲染。

### R2：进度语义与恢复稳定性（R1 后）

目标：确认现有比例进度在排版变化后的实际误差，按证据决定是否扩展契约。

1. 在字号、列宽、窗口尺寸、滚动 / 屏幕翻页切换与清正文前后，比较关闭重开后的可见段落位置；保留章末 100% 的现有行为。
2. 如果误差超过一屏，再设计段落下标与段内字符偏移作为锚点，保留现有 `scrollRatio` 兜底，并制定旧进度迁移。
3. 对章节长短差异明显的书验证全书百分比；如保留章节等权计算，明确标为估算，若改算法则说明与旧显示值的关系。

验收：对已实施的路径，重开位置与离开处相差不超过一屏；旧书库可直接打开。若涉及 `ReadingProgress`、IPC 或磁盘字段，由协调者按 `AGENTS.md` 审核并合并补丁。

### 候选项：CSS 多栏真分页

现有连续滚动与可视页翻屏已经覆盖基本阅读方式。只有实际使用证明两者都不足时，才单独评估 CSS 多栏真分页；评估必须覆盖窗口缩放、选区、标记坐标、搜索定位、TTS 和进度恢复。它不属于 R0～R2 的默认交付范围。

## 6. 数据与技术边界

### 保持不变

- 章节正文继续只渲染纯文本，禁止 `v-html`。
- 标记坐标继续基于规范化正文，不因主题或分页改变。
- AI 仍然只读取已读边界内材料，不剧透未读内容。
- 遵守 `AGENTS.md` 的技术约束：不引入 native 模块；本阅读体验方案不为浏览、下载、账号或云同步能力排期，不能将它们写成项目禁项。

### 两个阅读界面的分工（刻意决定，不是待补的缺陷）

同一本小说有两个阅读界面：书库的本地阅读器（`Reader.vue`）与内置浏览器的网页阅读模式（`Browse.vue` 的 `.web-reading-stage`）。两者的边界是**正文是否留在本机**：

- **共用**：阅读主题色（`@shared/readerTheme` 单一真源，两界面同一主题渲出同一纸色）、`ReaderPrefs` 全套排版偏好（字体/字号/行距/列宽/段间距/缩进/行焦点/阅读方式）、规范化正文坐标空间、划线与备注的语义（含 `noteSource` 的 user/ai 之分）、书内搜索、TTS。
- **各存各的**：本地标记挂 `bookId` + `chapterId`（`<bookDir>/annotations.json`，随书库备份）；网页标记挂**规范化章节地址**（`web-annotations.json`，不进备份）。同一本书两条路径的标记互不可见，这是刻意的——网页侧不落正文，本就没有可比对的 `chapterId`。
- **AI 只有一套**：跨章 AI（前情提要、人物与伏笔记忆、带依据问答、读完一章自动整理）依赖**能回头重读已读章节**。网页阅读模式刻意不存正文（`readingSession.ts` 只有 6 章内存 LRU、退出后 5 分钟回收），因此这些能力**只在本地阅读器提供**。网页阅读模式的「AI」面板给的是入口：就地可用的是选区级 翻译 / 解释这段（`ai.translateStream`、`ai.explainSelection`，都不依赖书库）；要跨章 AI 就「下载本书」，已下载则「去书库读这本」。

判定「这本网页书是否已下载」不需要新 IPC：网页书架 id 与下载书 id 都由 `canonicalBookId(host, catalogUrl)` 派生，同一本书两条路径得到同一个 id，渲染侧拿 `library.list()` 比对 `readingChapter.shelfBookId` 即可。

曾评估过「给网页阅读模式做正文落盘镜像、就地拥有全套 AI」的方案：它等于自动下载读者读过的章节，会新增一类长期磁盘数据、一套与下载书并行的书身份和两份互不相通的 AI 产物，而项目已有「下载本书」这条正路。**已否决**，不要再作为待办提出。

### 已有状态与持久化

以下交互状态当前只在阅读会话中使用：

- 工具栏是否展开。
- 当前抽屉。
- 临时沉浸模式。
- 选区工具条位置。

以下偏好当前已经持久化：

- 主题、字体、字号、行距、列宽、段间距、缩进、阅读方式、按段落聚焦。

### 进度的后续演进

当前 `ReadingProgress` 保存章节 ID、滚动比例和更新时间。R2 若测得清正文、字体或窗口变化导致超过一屏的恢复漂移，可按需新增段落下标与段内字符偏移；现有章节 ID 和滚动比例继续作为兼容与回退信息。

新增字段会涉及 `src/shared/types.ts`、`docs/ipc-contract.md`、`docs/disk-schema.md` 与旧书库兼容；依 `AGENTS.md` 由协调者审核共享契约和集成补丁，不由阅读工直接改动。

## 7. 成功指标

以下是 R0～R2 的验收目标；尚未实测的指标须在对应阶段留下证据：

1. **显隐与键盘**：静置和沉浸状态下顶部、底部工具层按规则隐藏；键盘能唤回、操作并退出，弹层和焦点不丢失。
2. **阅读布局**：正文不因工具显隐跳动；书脊和细进度条保持可用；1100×720、1366×768、1920×1080 下无横向溢出。
3. **真实性能**：在 Electron 中记录一万段章节的首屏、滚动、搜索和换章数据；如触发优化，长任务明显减少且核心阅读功能无退化。
4. **进度恢复**：章末仍显示 100%；跨字号、列宽、窗口变化和清正文重开后，若执行 R2 增强，位置误差不超过一屏。
5. **既有能力**：四主题、偏好保存、目录状态、预读、选区、TTS、AI、减少动态效果及纯文本正文回归通过。

## 8. 推荐实施顺序

按以下顺序推进，并在每阶段结束时复核是否需要下一阶段的改动：

1. **R0：修复工具显隐并验证键盘、焦点与弹层。**
2. **R1：测量真实大章；仅在证据触发时优化渲染。**
3. **R2：验证位置恢复与全书进度语义；仅在需要时扩展共享契约。**
4. **候选项：依据实际使用反馈单独决定是否评估 CSS 多栏真分页。**

如果只做一轮，先完成 R0。四主题、列宽、进度公式、章节预读等已实现功能只做回归，不重复开发。

## 9. R3：护眼压暗与续读可见提示（2026-10-18 增补）

- **护眼压暗**：`ReaderPrefs` 增加可选 `dim`（0–70，默认 0，经 `normalizeReaderPrefs` 四舍五入并夹紧，旧设置缺字段按 0 启动）。背景面板加"屏幕压暗"滑块，正文区叠一层 `pointer-events:none` 的黑色遮罩 `.reader-dim`，`opacity = dim/100`。z-index 取 15：高于正文(0)、低于翻章热区(18)与页码(26)，只压暗正文光、导航箭头与页码保持清晰且不吞点击。夜间主题之上仍可再压暗，解决"夜间仍嫌亮"。
- **续读可见提示**：打开书自动跳回上次位置时不再是静默跳转——仅当落在非首章或 `scrollRatio > 0.02` 时提示"已回到上次读到：第 N 章 · 章名"，从第一章从头读不打扰。纯界面改动，不动持久化。
- **全书完成进度与续读定位**本已存在（`全书约 X% · 本章 Y% · 还剩 N 章`，进度面板与底部进度轨双处；`loadBook` 读 `progress` 恢复位置），本轮不重复实现，只把静默恢复补成可见。
