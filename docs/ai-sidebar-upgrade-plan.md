# AI 侧栏升级：借鉴清单落地计划

分支 `feat/ai-sidebar`（worktree：`C:/codes/xsxz-ai-sidebar`），合并由用户决定。
基线是主工作区 2026-11-26 的当前状态（含未提交改动）。

## A. 消息级交互与引用可见性

- [ ] A1 `ai.replaceChat` 频道：整段覆盖问答历史，带校验与上限，destructive 分级。
      重问 / 编辑重发 / 删除此轮都靠它，不再往历史里追加重复轮次。
- [ ] A2 每条助手消息的操作条：复制、重问、编辑上一条并重发、删除此轮。
- [ ] A3 思考链：agent 模式的工具调用按消息收集，折叠展示（运行中自动展开）。
- [ ] A4 内联引用角标：结论正文里渲染 `[n]`，点击跳原文并高亮该段。
- [ ] A5 侧栏可拖宽，宽度持久化（默认 420，夹在 360–720）。

## B. 答案可信度闭环

- [ ] B1 结论必带逐字引文：模型返回 `{ text, citationIds, quote }`。
- [ ] B2 代码校验：`quote` 必须逐字出现在对应 citation 的 excerpt 里（空白归一后比较）；
      不通过就删这条结论，全删则按「无依据」拒答。
- [ ] B3 批量 judge：每条存活结论对照其引用段判 supported / not_supported；
      不支持即删。judge 本身失败（网络/格式）时保留结论，但标记 verification=not_run，
      界面必须明说「未运行校验」，不能伪装通过。
- [ ] B4 类型与界面：消息带 verification，界面显示已核验 / 部分删除 / 未运行校验。

## C. 检索与记忆（后续）

- [ ] C1 章节树检索兜底：没有向量服务时，用「卷 → 章」树 + 关键词打分选章，再进入现有证据流水线。
- [ ] C2 卷级摘要树：章摘要 → 卷摘要，刷新前情只读卷摘要 + 最近 N 章。
- [ ] C3 人物关系图：力导向 SVG，点节点看关系与「第几章起成立」。
