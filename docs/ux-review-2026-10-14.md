# 小说浏览器（spbf）使用体验报告

> 视角：一个挑剔、没耐心的真实用户。装了就用，不会读 README，出问题就骂。
> 日期：2026-10-14 ｜ 版本：0.1.0（工作树 b8c625d + 未提交改动）
> 测试环境：本机 Electron 43.4.0 真实进程（Linux，X11），非 Windows 打包版

---

## 0. 我怎么测的（可复现）

不是读代码猜的，是真机点出来的：

1. **真机全路径**：内置浏览 → 打开书站 → 下载本书 → 书库 → 阅读器 → 设置，全程用真实鼠标事件与 CDP 观察 DOM/截图。
2. **自建书站 fixture**（`/tmp/ux/`，已停服）：三套站点，覆盖真实国内小说站的三种编码现实
   - `5180` UTF-8 + `<meta charset>`（规范站）
   - `5181` UTF-8 **不声明 charset**（老站）
   - `5182` GBK + `charset=gbk`（国内常见）
   每站 12 章目录 + 正文页。
3. **对照实验**：同一份 2 章网文分别以 **CRLF** 与 **LF** 换行存盘，走同一条导入路径，比对阅读器渲染结果。
4. **代码级复现**：另有三路只读审查，用 esbuild 打包真实模块直接调用（extract / paywallUnlock / pageProbe / importTxt / listBooks / ocrText），并跑单个 vitest 文件；这部分结论标注为「代码级复现」。

截图见 `docs/ux-review-assets/`。

---

## 1. 一句话结论

**这软件做出来的东西比我预期好，但它在最基础的两个入口上会当场翻车**：Windows 用户的 txt 导进去排版报废；缺 charset 的中文站打开就是乱码、点下载还给一句答非所问的提示。功能面（阅读器、AI、备份、回收站）明显超出一份「第一版」该有的水准，可**容错与提示设计仍是「工程师视角」**——出问题时不告诉用户发生了什么。

- 能不能用：能。下载、阅读、书库、AI 通路都成立。
- 给谁用：能自己配站点规则、看得懂「pageKind」「failCode」的技术型用户。
- 不建议给谁用：只想「贴个链接就把书下下来」的普通读者——他们在第 2、3 条就会放弃。

## 2. 最痛的 6 条（按严重度）

### 2.1 【严重】Windows 的 txt 导进去，每章挤成一大坨 —— 实测复现

这是目标平台（Windows 10/11）上**几乎必然发生**的事：记事本、Word 导出的 txt 都是 CRLF。

- **现象**：导入后每章正文没有段落、没有缩进、没有段间距，一整章糊成一段。段落锚点、专注模式、分段朗读、划线定位全部一起失效。
- **复现**：同一份内容分别存 CRLF / LF，导入同一书库，打开第一章。
- **实测结果**：

  | 样本 | 入库正文 | 阅读器渲染段数 |
  |---|---|---|
  | `lf-novel.txt`（LF） | 无 `\r` | **4 段**（28/32/28/23 字）✅ |
  | `crlf-novel.txt`（CRLF） | 保留 `\r\n` | **1 段**（96 字一整块）❌ |

  对比截图：`docs/ux-review-assets/reader-lf-import.png`（正常）vs `reader-crlf-import.png`（糊成一段）。
- **根因**：`src/main/importTxt.ts:25,34` 用 `join('\n')` 拼行、正文原样落盘，`\r` 被保留；阅读器分段规则是 `split(/\n{2,}/)`（`src/renderer/pages/useTts.ts:4-6`、`src/shared/paragraphSearch.ts:16`），而 `\r\n\r\n` 中间夹着 `\r`，匹配不上。
- **一句话**：修一行 `body.replace(/\r\n?/g, '\n')` 的事，代价是现在所有 Windows 用户的第一印象。

### 2.2 【严重】缺 charset 的中文站 = 整页乱码，点下载只得到「这一页没有目录」

- **现象**：打开一个不声明 charset 的中文站，页面标题变成 `æ®‹ç» - æµ‹è¯•ä¹¦ç«™`，正文全是乱码。点「下载本书」，界面给的提示是：**「这一页没有目录。回到这本书的目录页再下载，或先在设置里配置本站规则。」** —— 用户看到的明明是目录页，提示却在怪他站错了页。
- **实测**：`http://127.0.0.1:5181/index.html`（UTF-8 无 charset 声明），标题栏、页面正文、下载探测全部乱码；点下载无弹窗、无 toast，只有那句提示。截图：`docs/ux-review-assets/browse-mojibake-site.png`。
- **更糟的后果（代码级复现）**：下载路径对正文**没有任何乱码判据**。`quality.ts` 体检无乱码规则，`extract.ts:377,388,399` 只查长度与中文占比，`download.ts:642,817,840` 直接落盘。实测把 latin1 乱码 1248 字、锟斤拷 1080 字喂给 `extractBody` → 全部 `ok:true` 原样入库。对照 `importTxt.ts:48-62` 有 GBK 探测，下载路径 grep `charset|TextDecoder|gbk` 零命中。
- **用户视角的诉求**：① 乱码时给一句人话（「页面编码未声明，可能显示为乱码」）；② 浏览页给一个手动切编码的入口；③ 入库前对整章做一次乱码体检并标 `suspect`，别把坏数据当 `ready`。

### 2.3 【严重】书库路径这个设置项，是个陷阱

设置 → 书库 → 路径输入框，看着就是个能改的普通设置项。**但它改了不生效，也没有任何反馈**。

- **实测**：输入 `/tmp/ux/library` → 失焦 → 无 toast、无「未保存」标记 → `~/.config/spbf/settings.json` 里没有 `libraryPath` 字段 → `/tmp/ux/library` 目录根本没创建。静默丢弃。
- **唯一生效路径**：点「搬迁书库」按钮。而它的语义是**复制整个书库到新目录并切换**（`Settings.vue:314-339` → `library.migrate`），会弹确认框、会真的拷文件。
- **为什么这是陷阱**：同一个设置页里，下载速度是点一下就存（`Settings.vue:300-312`），唯独路径要按一个叫「搬迁」的按钮——用户想「换个目录读已有的书」会触发全库复制，想「只是改个路径」则以为已经改好了，下次开软件发现没变。
- **建议**：路径框旁边给明确的「保存路径」动作 + 未保存提示；「搬迁」作为独立功能（复制/移动二选一），两者分开。

### 2.4 【严重】下载路径对「坏正文」零校验，坏数据直接当成品入库（代码级复现）

三条实测（都是拿真模块跑出来的，不是推测）：

1. **广告被当正文**：付费墙页面上只要有非正文 iframe（≥200 有效字、≥120 中文字）或 `window` 上匹配 `/chapter|content|read|novel|book|story|data|state|page|payload/` 的字符串（比如 GTM 的 dataLayer），探测就把这段文本并进来当解锁结果。实测：广告 iframe 文本并进 `fixtures/paywall-vip.html` → `ok:true, unlockedBy:'embeddedJson', body=858 字广告文案`。根因是 `pageProbe.ts:54-73` 全收 iframe 与 window 字符串，`paywallUnlock.ts:139-152` 只校验长度和中文占比，没有「不是广告 / 不是跨域 iframe」的约束。
2. **字形替换章绕过 OCR**：正文被换成私用区码点（U+E000–U+F8FF）时，只要 DOM 文本 ≥80 有效字符就当正常章入库（`extract.ts:366-409,750-756`）。PUA 判据只存在于恢复路径（`paywallUnlock.ts:126-133,144`），OCR 只在 `failCode==='Paywall'` 时才跑（`download.ts:1294-1314`）。实测 600 个 PUA 字符的章节页 + `{ocrUnlock:true}` → `ok:true`，OCR 分支压根没进。**站点级 OCR 开关形同虚设。**
3. **正常章节被判成拦截页**（阻断级）：章节页任意元素文本或正文里出现 `请完成人机验证 / 检测到异常访问 / 点击按钮继续 / Cloudflare / Access Denied` 之一，`isInterceptedPage` 就会在**正文已抽全的情况下把 body 丢掉**（`extract.ts:461-470`、`bodyText.ts:8-10`）。注意它**没有字数门槛**（付费墙判据有 ≤800 字门槛）。实测：1100 有效字的正常正文 + 一句「Access Denied」→ `ok:false, failCode:'Intercepted'`；同一句放进内联 `<script>` → 同样被判拦截。更糟的是同类墙连撞 3 章会暂停，而 `resume` 只把墙章退回 `pending` 重跑（`download.ts:437-447`）→ **再撞同一堵墙，死循环**，界面上「我已处理好，继续下载」永远无效。

### 2.5 【严重】空章/占位章：每章白等 37–40 秒

- **代码级实测**：`waitUntilHydrated` 对空章一次耗时 **12205ms**，且 `isWallPageHtml`/`isHydratedHtml` 都判 false → 走满 3 次重试。合计 **≈37–40 秒/章**，还多发 3 次请求。
- 证据：`download.ts:494-498`（wall 通道不含 `BodyEmpty`）、`78-84`、`142-144`、`1340-1345`。
- 一本有几十个占位章的书，用户会以为软件卡死。

### 2.6 【严重】目录只有 1–4 章时识别失败，提示还跟事实相反

- **代码级实测**：1/3/4 章的目录页 → `ok:true, pageKind:'chapter', chapters:0`，并且**把页面简介当成了「本章正文」**（965 字）；5 章才识别成 catalog。证据：`extract.ts:208-214,229`（<5 放弃）、`155,581,707`（规则 <2）。
- 结果：预览「确认下载」→ 必然 `CatalogNotFound`。而提示是「这一页没有目录」（`download.ts:309,852-853`）—— 短篇、试读章、分卷页都会踩。

## 3. 分模块体验

### 3.1 内置浏览

**好的**：地址栏、后退/前进/刷新、站点提示、下载本书、更多工具、阅读模式、上一章/下一章、缩放、网页查找、点选隐藏、去广告开关，该有的都有。站内导航正常，页面渲染正常。

**问题**：
- **无编码处理入口**（见 2.2）。国内小说站 GBK 居多，声明正确时没问题（实测 5182 站正常解码），一旦声明缺失/错误就是死局。
- **首次进入不知道能干嘛**：没有引导，没有「贴个网址试试」的示例；下载本书按钮的可用状态也没有解释（比如当前页不是目录时它仍然可点，点了才给提示）。
- 阅读模式/上一章/下一章的快捷键只在工具栏小字里写着（`Alt＋↑ / Alt＋↓`），不看就不知道。

### 3.2 下载本书

**好的**：
- **提取质量真的不错**。本地书站下载 12/12 章，正文干净，`header/nav/footer` 的「广告位招租 联系站长」被正确剔除，书名「残经」、作者「佚名」、目录 12 章全部识别正确，2 秒下完。
- 下载前预览弹窗信息齐全：书名、作者、目录章数、前几章列表、正文样本（截图 `download-preview.png`）。
- 失败章节分类、质量体检（本次提示「质量检查发现 26 项疑似问题」）、付费墙 5 种恢复手段的代码与测试都在。

**问题**：
- 预览弹窗**没有「取消」按钮**（只有右上角 ×），确认按钮孤零零挂在左下角；样本区很小（3 行高）还要滚动。
- 预览样本固定取第 1 章（`download.ts:860-871`）——第 1 章恰好是墙/空章时，用户只能盲确认。
- 预览阶段的墙/空正文只有一句浮层提示，**没有下一步动作**；`CATALOG_PAGE_HINT` 是不可达死代码（`download.ts:823-855`）。文档承诺的 `pageKind: 'catalog'` 与实现不符（实测 login-wall / chapter-empty 都返回 `'unknown'`）。
- **书库发起的下载没有取消入口**。浏览页的取消按钮要求 `downloading===true` 且只在浏览页自己发起时为真（`Browse.vue:1261-1279,865-885`）；从书库点「检查更新」起的下载，全局没有 cancel（`App.vue:184,256-262` 只显示进度条，书库卡片无取消）。我实测触发了一次「全部检查更新」，进度条在跑，**我找不到任何停止按钮**。
- 检查更新时同名不同 URL 的章被静默吞掉且不计入 `added`（`library.ts:303-339`、`download.ts:1452-1460`）；书已下完再点下载，首帧就显示「完成」。
- 目录分页只下第一页；续页 >3 静默丢弃；`canonicalizeUrl` 把 `?page=N` 全抹平（`urlHash.ts:35-38`）→ 分页目录会丢章。

### 3.3 书库

**好的**：卡片信息密度合适（封面占位首字 + 配色、书名、作者、完整/部分标签、已读进度、全书概览带「含剧透」标记）；菜单齐全（编辑信息、前情提要、检查质量、检查更新、导出 txt/epub、移入回收站）；有回收站、有整库备份与恢复、有每周自动备份；书多了也不卡（25 本实测流畅）。

**问题**：
- **「移入回收站」没有确认框、没有成功反馈**。我实测点下去，界面没有任何变化提示，只能靠书消失了来判断。误点成本虽小（可恢复），但心理上很糟。
- 进度文案有歧义：卡片写「已读 5 / 共 100 章」，那个 5 是**当前读到第几章**，不是已读完成数（`libraryCard.ts:134-135`）；排序里的「最近更新」实际是「最近读过」，点开一本书就把它顶到最前（`library.ts:619-624,263-267`）。
- 每次进书库/删书/导入都**全量重建索引 + 逐章读文件**（`library.ts:465-467,398-421,274-300`），与 `docs/disk-schema.md:52` 写的「缺失或不一致才重建」不一致。代码级实测：1600 章单本 `listBooks` 167/266/223ms。
- 删除只 `rename` 进 `__trash__`，**不释放磁盘**，回收站不显示占用、不自动清理（`library.ts:474-488,535-555`）。
- 失败章列表没有「打开这一章」；「去浏览页」不导航到具体 URL（`App.vue:161-168`），而 `openUnblock` 明明已经挂在 preload 上（`preload/index.ts:177-180`）。

### 3.4 阅读器

**好的**：这是产品里最成熟的一块。书页居中、衬线字体、行距舒适；外观面板参数齐全且即时生效——字体（宋体阅读/系统黑体/等宽）、字号、行距、列宽（窄/中/宽）、段间距、首行缩进开关、行焦点（关/1/3/5 段）；目录/进度/背景/字体右侧浮动面板；顶栏有书架、搜索、书签、朗读、翻译、设置、浏览、全屏。截图：`reader-appearance-panel.png`。

**问题**：
- **进入阅读器后整个应用导航被 `v-if` 移除**（`App.vue:231`：`v-if="!(tab === 'reader' && currentBookId)"`），返回靠**悬停才出现**的工具栏（`.reader-tools-hidden { opacity:0; visibility:hidden; pointer-events:none }`，`Reader.vue:4049-4053`）。我第一次进来时以为被困住了——顶栏和底栏都是透明的，必须把鼠标蹭到窗口最上面才出现「书架 / 设置 / 浏览」。**沉浸是好事，但首次要有一次提示或短暂显示**。
- 顶栏图标（书架/搜索/书签/朗读/翻译）**没有文字标签**，全靠 tooltip。
- **跨书切换会打开新书的「同序号章」**：书 A 读到 c0005，回书库点书 B → 直接打开书 B 的 c0005，还沿用书 A 的滚动比例，书 B 自己的 `progress` 被跳过（`Reader.vue:1250-1300`，1285-1290 命中同 id 就 return，1293-1299 的 progress 分支被跳过）。书 B 没有该 id 时才弹「原章节已不存在，已打开第一章」。
- 阅读器里**保留站点声明垃圾段**：下载的每章末尾都留着「本站所有小说为转载作品…」（入库 `body` 里就有），阅读时很显眼。通用提取难以区分它和正文，但**至少该在体检里标出来**。
- 键盘只认 Space/Shift+Space/J/K，**PageUp/PageDown/Home/End 完全没反应**（`readerHelpers.ts:176-201` 未映射，滚动容器无 `tabindex`，`Reader.vue:2808`）；`←/→` 是整章跳转。
- 目录里点当前章会把位置重置到章首，并可能把进度写成 0%（`Reader.vue:1615-1618,1318-1324,1343-1351`）。
- 目录「已读」角标按 progress 章位置推（`readerHelpers.ts:81-91`），从第 1 章跳到第 100 章后，2–99 章全被标成已读。
- 超长章节分批渲染期间落盘的进度按 `renderedCount/总段数` 缩放（`Reader.vue:1544-1548`），恢复锚点没有正文指纹校验（`1464-1488`）——清正文/重下后章内位置会漂。
- `readerPerf` 的 100ms 性能门是死代码，实际用固定 `paras.length > 2000`（`readerPerf.ts:5-9`、`Reader.vue:2808,4241`）。

**txt 导入的额外问题**（除 2.1 外）：
- 切章正则过窄：「第 1 章」（数字与「章」之间有空格）或标题行 >60 字符 → **整本不切章**，出现一本只有「正文」一章的书（`importTxt.ts:14`，代码级复现：两种样例章数均为 1）。
- 番外/楔子/序章/后记**不进目录**（并进上一章），「第一卷」被当章（同上，代码级复现）。
- 编码回退只覆盖 UTF-8 / UTF-16LE(BOM) / GBK / GB18030；**Big5 会静默乱码**且无提示、无手动选编码（`importTxt.ts:45-63`，推理未实测）。
- **导入没有进度提示**，按钮不置灰；且每章都对整本 `book.json` 读改写 + fsync（`importTxt.ts:87-92`、`library.ts:1142-1160`）。代码级实测：200 章 2.64s、800 章 13.2s、1600 章 **33.8s**，单章成本随规模上升；Windows + Defender 只会更慢。导入期间重复点击会立刻返回并打开一本章节还在写盘的书。

**epub 导入**：插图页整页消失（`img` 无 alt 时 `body` 为空被直接丢，`importEpub.ts:131-137`）；正文页首行重复一次章名；fallback 章号用 spine 下标（`134`），前面被丢弃的封面/版权页仍占号 → 目录跳号；封面永不提取，书库卡片只有色块首字。

### 3.5 设置

### 3.6 AI

**好的**：没填 Key 时**在花钱和排队之前**就拦住（`index.ts` 8 处统一提示「请先在设置中配置 API Key」）；请求不卡界面——双车道调度，后台任务让位、交互任务可抢占共享资源，用户点「停止」只杀交互车道（`aiScheduler.ts:82-95,150-173`）；流式 stage/chunk 推送正常（`Reader.vue:2549-2570`）；有额度护栏与「单次输入提醒阈值」。

**问题**：
- **未填 Key 时没有「去设置」入口**。AI 面板只写「模型服务：未配置」（`Reader.vue:2968`），全文件唯一的「去设置」按钮是 TTS 的（`2771`）。清正文/摘要的失败只闪一下 toast。
- **自动追剧（读完一章自动整理）触发条件比界面写的严得多，而且静默失败**：
  - 面板文案写「离开已读超过 **90%** 的章节时上报排队」（`Reader.vue:3009`），实际门槛是 **99.9% 且必须滚到底**（`Reader.vue:1312,1432-1434`）。按文案读到 95% 切章 → 静默漏章。
  - **一屏读完的短章永远不触发**：`chapterScrollRatio` 在无可滚动距离时返回 0（`readerHelpers.ts:19-23`），`0 < 0.999` → 不上报、不入队。用户点「下一章」什么都不发生，面板一直「待整理 0 章」，没有任何解释。
  - 旧书升级后，未点「确认旧进度为已读」之前历史章永远不排队（`Reader.vue:2961-2965`、`readFrontier.ts:92-124`）。
- **证据问答对 JSON 形状零容忍、无降级**：只认 `{answer, claims:[{text,citationIds}]}`，还要求 `answer` 等于各 claim 拼接（`aiEvidenceQa.ts:84,94-113`），没有 v1 `{answer,citations}` 回退。换自定义兼容服务或本地小模型 → 整条聊书失败，报「模型没有按结论返回证据」，重问同样结果。
- 错误提示夹英文原始报文：映射只覆盖 401/402/403/408/429/5xx，**404/400（地址少 `/v1`、模型名不存在）会落到 `AI 请求失败 (404)：{响应体前 200 字}`**（`ai.ts:168-176`）；网络类不区分「地址写错」与「断网」（`179-187`）。
- 未信任的自定义地址抛的是「告知」文案而非错误（`settings.ts:106-113`），也不提示「回设置页保存/测试连接以确认信任」。
- 四项功能（清正文 / 翻译 / 本章摘要 / 聊书）入口与失败态不统一，没有统一的「失败原因 + 重试」；清正文和翻译的「停止」只在输出面板里。
- 花费只有 tokens 与「不计算金额」，月度额度是抽屉里一行小字；设置页只有阈值输入，**没有「本月已用/剩余」看板**。
- 只要 follow 模式不是「手动」，阅读器就每 3 秒轮询一次，成本是 O(已读章数) 的读盘 + sha256（`Reader.vue:243,1907-1938` → `index.ts:258-263,241-256`）。
