## 0. 结论先行

- 在现有阅读器旁新增**渲染层级**的「真实书籍」模式：经典模式与真实书籍共用全部数据层（书库、章节、标注、进度、偏好），渲染层完全分开，互不侵入。
- 新模式的**内部标识**用 `bookView: 'classic' | 'realbook'`，不复用也不扩展 `ReaderReadingMode`（`'scroll' | 'screen'`）——那个字段连同「阅读模式」一词已被网页阅读覆层（`Browse.vue` 的 `setReaderPref('readingMode', …)`）与本地字体面板占用，对外命名只用「经典模式」「真实书籍」。
- 真实书籍需要**新的文本分页引擎**：`readerPager.ts` 的全部导出函数输入输出都是 `scrollTop`（见 §5），只能给出滚动落点，给不出「一段文字属于哪一页」，不可复用。
- 位置模型以**段落锚点为唯一真源**（`ReadingProgress.paragraphIndex / paragraphOffset`，`types.ts:49`），页码只是排版缓存（§4）。`scrollRatio` 仍是经典模式落点，两者按规则换算（§4.3）。
- 实施顺序：M1 数据层与标注扩展（3.1/3.2）→ M2 真实书籍渲染 MVP（分页 + 1.2 翻页拟真 + 1.3 缩放）→ M3 1.1 俯仰视角 + 书厚 + 页面装饰（E3–E6，已细化为开发计划）→ M4 2.2 思维导图 → M5 2.1 **平面地图页**（腾讯地图 2D 底图 + 地名/POI，Key 由用户自备，§5.5）。可互动 3D 地球仪不在本方案范围，另立项（§9）。
- `docs/reader-experience-upgrade.md` 的「连续滚动为主、屏幕翻页为辅」「CSS 多栏真分页仅作候选项」结论**只对经典模式有效**；真实书籍是独立渲染层，不受该结论约束，也不回改该文件（§8）。

## 3. 位置模型：段落锚点为真源，页码是排版缓存

### 3.1 现状

`ReadingProgress`（`src/shared/types.ts:49`）字段为 `chapterId`、`scrollRatio`、可选 `paragraphIndex / paragraphOffset / bodyHash / renderedRatio`、`updatedAt`——只有滚动比例与段落锚点，**没有**页码、pageIndex 或阅读界面标识。真实书籍若只用 `scrollRatio` 恢复位置，窗口缩放、字体改动、双页/单页切换都会让同一比例对应不同文字。

### 3.2 设计

- **真源不变**：真实书籍沿用规范化正文坐标（按空行切段、丢空段后 `'\n\n'` 连接，与 `Annotation` 同一坐标系）。保存进度时写 `paragraphIndex + paragraphOffset + bodyHash`，与现有字段一致，**不新增磁盘字段**。
- **页码是缓存**：真实书籍渲染层内部维护「排版签名 → 页表」缓存。排版签名 = 字号 + 行距 + 版面宽高 + 单/双页 + 字体。页表是 `Array<{ firstParagraph: number; firstCharOffset: number }>`。排版签名变化（缩放、窗口 resize、设置变更）即整表重算，页码不落盘。
- **恢复**：打开书 → 用锚点（段落下标 + 段内偏移）在分页引擎中查找所在页 → 直接翻到该页。旧书只有 `scrollRatio` 没有锚点时，按现有回退规则（`types.ts:53` 注释：缺省回退 `scrollRatio`）先估段（复用 `paragraphIndexForRatio` 思路），误差按「不超过一屏」验收，与经典模式 R2 的口径一致。

### 3.3 两种模式互转

- 真实书籍 → 经典模式：取当前页首锚点，在经典模式 DOM 中量出该段 `top`，换算 `scrollRatio = top / scrollableDistance` 落点，复用现有 `collectParagraphSpans`（`Reader.vue:1094` 附近）。
- 经典模式 → 真实书籍：取当前视口顶所在段锚点（现有 `paragraphAnchor()` 已产出该值，`Reader.vue:1731` 处进度对象即用它），真实书籍分页引擎按锚点查页。
- 模式切换本身**不触发进度写盘**（已核对：`readingMode` 变更只走 300ms 防抖的 `scheduleReaderPrefsSave`，`Reader.vue:2009/2032/2063/2090`；进度写入口 `createReaderProgressWriter` 只由滚动与换章/切书/关窗触发，`readerProgressWriter.ts:21`）。切换时位置以内存中的当前锚点即时换算，不依赖上一次落盘。
- 但要注意 `writeNow` 的捕获时机：`captureProgressWrite`（`Reader.vue:1723-1740`）在调用那一刻从 `contentRef` 抓取滚动位置与锚点，真实书籍下 `contentRef` 不再是滚动容器。实施 M2 时必须让 capture 按当前 `bookView` 取锚点——真实书籍侧从页表反查当前页首锚点；否则关窗/换章时的 `writeNow` 会抓不到位置或抓错。这是位置模型落在锚点（而非页码）上的第二个原因：两种模式能给出同一种锚点格式。

## 4. 分页引擎：为什么 readerPager.ts 不可复用

已通读 `src/renderer/pages/readerPager.ts`（238 行）全部导出函数：

| 导出 | 输入 | 输出 |
| --- | --- | --- |
| `visualPageCount` / `scrollTopForVisualPage` / `visualPageIndex` / `visualPageIndexFromRatio` | `scrollHeight / clientHeight / scrollTop` | 页数或 `scrollTop` |
| `scrollTopForParagraphPage` | 段落 spans + `scrollTop / clientHeight / direction` | `scrollTop` |
| `snapScrollTopToParagraph` | 段落 spans + `scrollTop` | `scrollTop` |
| `adjacentVisualPage` / `visualPageLabel` | 页下标、页数 | 页下标、标签 |
| `estimateParagraphHeight` / `placeholderHeight` / `windowBoundsFor` / `paragraphIndexForRatio` | 段落 spans 或计数 | 估算值、窗口区间 |

除页码工具（`adjacentVisualPage` / `visualPageLabel` 只做页下标算术与格式化）外，其余函数的坐标语言全是「滚动像素」：给定一个 `scrollTop` 给出下一个 `scrollTop`。真实书籍的问题相反——**给定一页的版面尺寸，求一段文本从哪到哪属于这一页**，正文根本不存在 `scrollHeight`，也没有可复用的量测节点。因此需要新分页引擎 `realBookPager.ts`：

1. **离屏量测**：一个与真实页等宽等高的隐藏量测容器，逐段（必要时逐行）流入，记录每页起始的 `(paragraphIndex, charOffset)`。正文是纯文本段落，量测成本可控（正文是纯文本，与经典模式的文本处理基准同量级；大章的分批处理策略见 `docs/reader-experience-upgrade.md` R1 结论）。
2. **增量与缓存**：只在排版签名变化时全量重排；翻页、窗口 resize 失焦后重进时读缓存。长章（项目已有超长章）允许按「先排 N 页、边读边续排」的惰性策略，与经典模式 `windowBoundsFor` 的窗口化思想同构。
3. **单元测试友好**：分页函数输入是段落数组 + 版面尺寸，输出页表——纯函数，不碰 DOM 即可在 vitest 中验证断页正确性（段不腰斩、段间距不跨页溢出）。
4. **字体就绪**：量测必须等 `document.fonts.ready`（自定义手写字体加载完成后）再跑，否则换行宽度与真实渲染不一致，页码会漂。

## 5. 渲染与 3D 技术路线（1.1 / 1.2）

### 5.1 选型：CSS 3D 优先，WebGL 仅作后备

| 路线 | 覆盖 | 判断 |
| --- | --- | --- |
| **CSS 3D（推荐，MVP）** | 双页摊开、`perspective` 俯仰、`transform-origin` 在书脊的整页翻动、卷角（子元素叠加渐变 + `rotateY` 近似）、书厚（上下堆叠的伪页边条） | Electron 渲染进程即 Chromium，`transform-style: preserve-3d`、`backface-visibility`、`perspective` 均为稳定支持的标准特性；正文仍是 DOM 文本，选区、搜索高亮、标注渲染全部沿用既有实现；**1.1/1.2 阶段零新运行时依赖**（2.1 的地图自计外部 JS API，见 §5.5） |
| **WebGL（后备，仅评估）** | 真实网格弯曲的卷页、连续书厚曲面 | 需把文本渲染进纹理或维护 DOM/WebGL 双轨，选区与标注坐标全部断掉，且引入 three.js 级别的依赖。仅在 §5.1 升级条件成立时单独立项评估 |

结论：1.1/1.2（M2/M3）用纯 CSS 3D + 少量 Canvas（仅卷页阴影叠加，可后置），**不新增任何运行时依赖，不引入 three.js**；`page-flip`（StPageFlip）这类翻页库作为 M2 的备选记录在案——它自带卷页形态，但会把正文吞进它的 DOM 结构，与选区/标注的兼容必须先做 spike，默认不采用。

**升级到 WebGL 的判断条件**（任一项成立且产品必须保留该效果时才立项，不预设会触发）：

1. 效果图中的翻页需要**连续曲面弯曲**（页面沿翻动方向呈弧面，而非平面绕脊旋转），CSS 3D 平面变换 + 渐变阴影在真机上做不到可辨识的近似。
2. 书厚需要呈现**连续曲面/可拨动的页堆实体**，伪页边条 + 厚度渐变不足以形成效果图中的层次。
3. 目标机型上 CSS 3D 翻页/俯仰持续掉帧或文本模糊，优化到可接受范围的代价高于引入 WebGL 渲染文本的成本。

以上三条均不成立时维持 CSS 3D；判断依据是 §5.4 的效果图验收清单逐项对照，而不是主观偏好。

### 5.2 翻页拟真（1.2）的落点

- 结构：`.real-book-stage`（perspective 容器）→ 左右两张 `.page`；翻页时插入一张翻动页，`transform-origin` 对齐书脊，`rotateY` 0°→−180°，配合 `backface-visibility: hidden` 露出背面。
- 书厚：页堆用若干固定伪页 + 按阅读进度的厚度渐变条（顶部露出已读侧纸边、底部剩余侧），俯仰时视差自然出现（§5.3）。伪页层数在设计时作为起始值，最终取多少**待效果图核实**，不把效果图的层数当成已确认事实。
- 尊重 `prefers-reduced-motion`：与 `pageByScreen` 现有做法一致（`Reader.vue:1109` 读取该媒体查询），减动效时翻页退化为直接切换双页内容，无动画。

### 5.3 俯仰视角（1.1）的落点

- 整个书台容器固定一个 `rotateX(pitch)`（起始角度在实现时定，可拖拽调节，**具体角度待效果图核实**），拖拽仅改变视角不改页码；双指/滚轮缩放走 `scale`（1.3 的真实书籍实现点）。
- 俯仰 + 书厚伪页边条即产生截图中的「看到已读与剩余部分书厚」效果；不需要 3D 引擎。
- 性能护栏：3D 容器内不做无限层叠（伪页上限 8 层），`will-change` 只挂在翻动中的页；章节切换时先平放再翻页，避免大面积重排叠加透视。

M3.5 拟真卷页（2026-11-06，本轮）：

- 起因：用户反馈「翻页手感不对，应该是模仿真实翻页」。此前翻页是整页 `rotateY` 平面旋转，纸面始终是一张硬卡片，没有弯曲、没有投影、也没有厚度变化。
- 新增纯函数模块 `src/renderer/pages/realBookFlip.ts`：把翻动页切成若干竖带，整张纸视为首尾相接的折线，从书脊逐带累加转角，位置是转角的积分。卷曲量取 `sin(πt)`——中段最大、两端归零，使起翻和落位都是直纸。纸的挺度有上限（`FLIP_MAX_BEND_DEG = 72`），避免一页宽内卷成筒。
- 折痕走向：自由边进度用 `1-(1-s)²`（约 75% 行程即到位），书脊侧进度用 `s^1.6`（前 20% 不动），两者不同步才形成从外缘走向书脊的斜折痕，而不是整页同步转动的硬卡片。
- 渲染：`RealBookStage.vue` 按竖带渲染，每带一条 `translate3d + rotateY`，纸面接近侧对观者时正文按 `cos` 淡出——竖带是按平面拼的，越斜越糊，几条带的字互相压住会像「纸上糊字」；真转到那个角度时本来也只剩纸色与明暗。
- 内容与投影：翻动页正反面改为同一张纸的两面（`flipSheetPieces`），背面接下一页会在落定那帧跳页；纸抬起的一侧立刻换成翻页后的内容，落下的一侧保持旧内容到落定。新增 `.real-book-cast` 投影层：抬起侧起手压暗、落下侧临落位才变暗。
- 参数：`FLIP_SLICE_COUNT` 8 → 12（12 条在 72° 弯度下每条约 6°，断行只在带边界拐一下；再往上换不来肉眼可见的改善，只换来起手卡顿）；`FLIP_DURATION_MS` 520 → 700（卷页需要更长的行程才不像弹跳）。
- 遗留：竖带是分段折线而非连续曲面，段数再多也只是逼近；正文接近侧对观者时被按 `cos` 淡出，此时翻动页只剩纸色与明暗，不带可读文字。
- 验收证据：`realBookFlip.test.ts` 9 项、`RealBookStage.ui.test.ts` 17 项、`Reader.realBook.ui.test.ts` 10 项全过；`npm run typecheck` 与 `npm run build` 通过；真起 Electron 在 30%/45%/60%/85% 四个进度截图核对过页形、投影与左右页内容；`npm run e2e:realbook-selection` 18 项全过（俯仰选区未受影响）。全量套件 1663 项中 2 项失败（`src/main/settings.test.ts` 的 `bookView` 缺省回退、`src/main/agentCapabilities.contract.test.ts` 的清单条数），均属主进程层既有欠账，与本轮未触碰的渲染层改动无关。

**风险**：

- 合成层开销 → 伪页层数上限 8、`will-change` 只挂在拖拽与翻页进行时；拖拽用 `requestAnimationFrame` 节流状态更新。

## 8. 与 reader-experience-upgrade.md 的关系

`docs/reader-experience-upgrade.md` 的核心结论「**连续滚动为主，屏幕翻页为辅**；CSS 多栏真分页仅在两者都不够时评估」（其 §1、§5 候选项）是在只有经典模式的前提下做出的，**仅对经典模式有效**。本文档不推翻它，也不回改该文件：

- 经典模式（`bookView === 'classic'`）继续遵循该文档的全部结论与验收口径。
- 真实书籍是新增的独立渲染层，其分页是**文本断页**而非该文档讨论的 CSS 多栏滚动分页——该文档「CSS 多栏真分页仅在必要时评估」的候选项结论对真实书籍**不适用、不约束**。
- 该文档 §6 的不变约束（正文纯文本、禁 `v-html`、标注坐标基于规范化正文、AI 只读已读边界、不引入 native 模块）对真实书籍**同样生效**，M1–M5 均不得违反。
- 该文档 §6 已界定「本地阅读器 vs 网页阅读模式」两个界面的分工；本文档新增的是**本地阅读器内部**的第三层区分（经典渲染 vs 真实书籍渲染），与网页侧无关。
